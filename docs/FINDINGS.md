# 研究发现：自进化 / 世界模型这条路，走通到哪一步

> 记录时间：2026-10-29 晚，2026-10-30 凌晨补入 gomoku 域（§3.5）。
> 前三个域都在跑，数字会变；结论除非被新数据推翻，否则不改。

---

## 一、先给结论

分成三层说，因为三层的结果完全不一样：

| 层 | 问题 | 结论 | 证据 |
|---|---|---|---|
| **机制层** | 自博弈 + 搜索 + 难度自迭代，这套东西转得起来吗？ | ✅ **转起来了** | 四个域都在无人工干预下跑了几十到几千代/局，难度真的升了，冠军真的变了；换成梯度方法（gomoku）机制照样转 |
| **评估层** | 评估器能不能持续给出有效梯度？ | ⚠️ **两种崩法** | 饱和型：code 域冠军 99.6% 满分，梯度归零；缺维型：gomoku 域所有离线指标健康，接进搜索后手数从 44.6 腰斩到 21.2（§3.5） |
| **世界模型层** | 这算不算"世界模型"？ | ❌ **还不算** | 现在有的是**课程（curriculum）**：5 个难度旋钮 + 平台期触发升级。世界不会预测"你这么做会发生什么"，只会调参 |

一句话：**自进化这条路走得通，但它的天花板不在搜索算法，在评估器。**

补一句（2026-10-30）：**评估器有两种坏法。** "太松"（冠军满分、梯度归零）一眼可见；"缺维"（指标全健康，但缺了决定胜负的那个维度）必须靠 A/B 才抓得住。gomoku 域是后者的标本，见 §3.5。

## 二、机制层：确实转起来了

### 2.1 三个域的三种命运

同一套骨架，换三个世界，跑出三种完全不同的结果——这本身就说明机制不是"写死能过"的：

**duel 域（格斗）—— 收敛成功，但趋同**

- fit 从 0.508 单调爬到 1.126，最高 1.139
- 61 代后代际漂移已经把「反击流」推到 20/25 的绝对多数
- 冠军长这样：`aggr=0.976 guard=0.982 kick=0.036 dist=0.89 react=1`
  → 读作「贴身猛攻 / 见招就挡 / 几乎只用拳 / 保持 0.89m / 反应 1 帧」
- **这是真收敛**：格挡偏置顶到 0.98、踢几乎弃用，符合"拳的每秒伤害更高"这条规则事实（拳 23.3 vs 踢 22.0）
- **但也是问题**：20/25 都是反击流，种群多样性 0.207 在往下走。再跑下去会锁死在局部最优

**sgs 域（卡牌）—— 梯度健康，一直在挣扎**

- fit 0.573~0.896 之间波动，949 代**没有一次满分**
- mean 稳定在 0.479 左右，div 0.16~0.19
- 难度 Lv4 全开（初始手牌/杀密度/桃密度/起始血量）
- **这才是健康的自博弈**：冠军始终够不着天花板，选择压力一直存在

**code 域（编程）—— 被打穿了**

- 2302 代，**3603/3617 条冠军记录 fit=1.000**（99.6%）
- 难度 Lv5 五维全开也一样满分
- 冠军基因退化到极端值：`retry_cap=8 parallel_try=5 scaffold=0.999`
- 这不是"模型很强"，是**评估器坏了**——详见下一节

### 2.2 难度自迭代真的会触发

不是每代都升，是等 EMA 进平台期才升：

```python
tail = hist[-10:]
spread = max(tail) - min(tail)
if spread >= 0.01: return False   # 还在涨，不升
# 平台了 → 挑一个维度 +1（优先开还没开过的维度）
```

**后来补了一条更关键的判据：冠军饱和。**

最近 10 代里 ≥8 代 `best_fit ≥ 0.999` 也会触发升级。补这条的原因：只用 EMA spread 会漏判。code 域 best 几乎恒为 1.000，但偶尔夹一两代掉到 0.9x，EMA 就在 0.95~1.00 之间抖，spread 永远 > 0.01，于是 2300 代一次都没升过——不是没平台，是判据只盯着"均值稳不稳"，没盯"冠军是不是已经打穿评估器"。

实测触发记录（`data/*_levels.jsonl`，旧数据）：

```
code: gen 9  → size=1 scaffold=1
      gen 10 → +hidden=1（开始盲改）
      gen 11 → +resource=1
      gen 12 → +depth=1  ⇒ Lv5 全开
sgs:  gen 51 → hand=1 hp=1
      gen 52 → +tao=1
      gen 53 → +sha=1    ⇒ Lv4 全开
```

机制是活的。**问题是升到顶之后没有下一层了**——这是设计缺口，见第四节。

## 三、评估层：code 域为什么崩了

### 3.1 现象

2302 代，99.6% 满分。日志长这样：

```
[gen 2293] 难度Lv5(...) best 1.000 ema 1.000 mean 0.931 div 0.355 hof 1209
[gen 2294] 难度Lv5(...) best 1.000 ema 1.000 mean 0.863 div 0.406 hof 1210
```

`best=1.000` 连着几千代。mean 还有 0.86~0.93 的波动，说明种群内部有差异，但**冠军永远是满分**。

选择压力在冠军这一层已经完全消失：反正大家都能满分，选中谁全看运气。

### 3.2 三层原因，一层比一层深

**第一层：题太简单。** 最初只有 7 族（calc/lru/bisect/dedupe/palindrome/fib/stack），都是几十行的经典小题，注入的 bug 也是"一眼能看出来"的。

**第二层：笔太强。** 换成外部 LLM 当笔之后，哪怕是盲改（不给报错），它读一遍源码就能定位。探针实测（`probe_new.py`，6 个硬核族）：

| 族 | 喂报错 | 盲改 | 梯度差 |
|---|---|---|---|
| topo | PASS | PASS | 0 |
| merge | PASS | PASS | 0 |
| quicksort | PASS | PASS | 0 |
| bfs | PASS | PASS | 0 |
| kadane | PASS | PASS | 0 |
| **dijkstra** | FAIL | FAIL | 0（但都失败） |

**五族梯度差为零**——盲改和喂报错一样能修，说明"脑诊断"这个基因维度根本没起作用，笔自己就把活全干了。

**第三层（最根本）：难度维度选错了。** 我把难度理解成"bug 藏得更深"，但对抗一个强笔，"藏得深"没有用——它能通读源码。**真正难住强笔的不是隐蔽性，是规模和交互**：跨文件、超长上下文、需求自相矛盾、性能约束。

dijkstra 是唯一一个两道都 FAIL 的——不是因为它 bug 藏得深，是因为**堆优化 Dijkstra 本身就难写对**（松弛条件、堆的更新、重复入堆处理）。这反而是个提示：**题目的绝对难度比 bug 的隐蔽度更有效。**

### 3.3 这个失败有普遍性

任何自博弈系统都会遇到：**当你把评估器交给一个比被评估者更强的模型时，评估就失效了。**

AlphaZero 没有这个问题，因为围棋的胜负是客观的、不可作弊的。而"代码修没修对"这个判断，一旦由强模型来做，就等于让强模型替被评估者答题。

**所以评估器必须比被评估者"笨"且"客观"**——只看测试通过与否，不看代码写得好不好。这也是为什么 code 域的评估只用 `pytest` 真跑，不让 LLM 打分。

### 3.4 评估器防护：堵住作弊路径（新增）

一个更隐蔽的问题：笔可以改**测试文件本身**，把断言删掉、写成 `print("All tests passed")`，fit 立刻 1.0。这是业界文档里点名的 coding agent 经典作弊姿势——测试不过就改测试。

修复：`write_fix` 里加了 `_vet_patch` 白名单，只允许改 `env.editable` 里列出的文件（`= [bug_file]`）。越界的文件名（尤其 `tests.py`）会被拒绝，并计入 `env.cheat_attempts`。

```python
# 只允许改白名单里的文件；越界的记入 cheat_attempts，不静默丢弃
```

这个计数本身就是一个观测指标：如果 `cheat_attempts` 持续上升，说明评估器正在被攻击，比 fit 更值得盯。

### 3.5 第二种故障：评估器"缺维"（gomoku 域，2026-10-30）

code 域是**评估器太松**——冠军轻松满分，梯度归零，一眼可见。

gomoku 域暴露的是另一种，更难发现：**评估器没有被打穿，指标全部健康，但它缺了决定胜负的那个维度。**

#### 现象

gomoku 域训了一个双头网络（policy 225 + value 1），value 头用 Rapfi 每步的 `Eval` 分做软标签。训练完成后，所有离线指标都好看：

| 指标 | 数值 | 读作 |
|---|---|---|
| 值损 | 0.6849 → **0.5622** | 真的在学（此前 80 代卡在 ln2=0.6849，等于常数解） |
| 方向准确率 | 88.5% | 真的准 |
| 均势局面输出 | 0.755 / 0.429 | 真的有梯度（不饱和） |
| 标签标准差 | 0.11 → **0.275** | 十档分布均匀，常数预测 BCE 0.6935 = 纯随机 |

按 code 域的标准（看冠军有没有满分），这属于**完全健康**。所以直接接进搜索。

#### 结果：手数腰斩

严格 A/B：同一份权重、同一裁判、只切换搜索**叶子评估方式**，各 30 局。

| 叶子评估 | 平均存活 | 标准误 |
|---|---:|---:|
| 训练好的胜率头 | **21.2 手** | 1.3 |
| 7 个手写规则数字 | **44.6 手** | 0.8 |

差 23 手，**17 个标准误**。接入"学出来的"评估器，实战存活掉了一半。

#### 根因：它学的是形势好坏，不是还有几步死

对着具体局面看就清楚了：

| 局面 | 胜率头给的 | 真实含义 |
|---|---:|---|
| 对手活四（下轮必死） | 0.2 | "我快输了" |
| 对手活三（还能救） | 0.2 | "我快输了" |

两个值一样，但一个是**已经死了**，一个是**还能救**。搜索拿它当叶子，分不出该先救哪个，于是把救命的唯一一手让掉。

那 7 个手写数字很粗糙（数几个活三、几个活四，加权相加），但它**数的就是威胁等级**：活四权重比活三高几个数量级。粗糙但排序是对的。

一句话：**胜率头会判断"形势好坏"，不会判断"还有几步死"。** 后者恰恰是五子棋——以及所有战术型博弈——最要命的信息。

#### 为什么数据量补不上这个洞

这批数据是按"最终胜负/Eval 分"标的，而 Eval 分本身是**静态形势分**，它不含"距离"。所以：
- 加数据 → 形势分预测更准 → 但仍然不含距离
- 加深搜索（depth 2→4）→ 实测 48.2 手掉到 32.6 手（n=10，样本不足但方向一致）

**坏评估器 + 深搜索 = 更确定地做错事。** 这是这个域第二个可复用的结论。

#### 给主命题的补充判据

原来那句话——"看冠军的适应度有没有顶到天花板"——只能抓住饱和型。补一条能抓住缺维型的：

> **评估器不只要"能排序"，还要"排的是对的那个序"。**
> 唯一可靠的验证是把评估器换进决策链，看实战指标。离线指标（损失、准确率、分布形状、是否饱和）全都可能骗人。

具体做法（本域实际用的）：`match_rapfi.py --leaf value|rule` 一个开关切换评估器，其余全冻住，各跑 30 局比存活手数。**没有这个开关，这个 bug 会一直藏着**——因为训练日志每一天都是"在进步"。

#### 这个失败也解释了 §3.4 的反常现象

同域还有一条看起来更荒谬的数据：19 万条 Rapfi 教材训练出的双头网络，实战 23.6 手；而最初那 7 个手调数字，25.3 手。

**神经网络输给手写规则。** 原因有两个叠在一起：

1. **复合误差**：教材全是「Rapfi 打 Rapfi」的局面，我们走出他不会走的棋之后，所有局面都在分布外（实测：Rapfi 首选与网络首选只有 37% 一致；同一局引擎评分从 531 掉到 140）
2. **缺维**：即使局面在分布内，它学的仍是形势分，不含威胁距离

所以在**有强规则先验的领域**，从零做模仿学习的净收益可能是**负的**——不如直接写规则。要翻过来，得同时解决这两件事，而第一件（DAgger 补分布外局面）只需 300 局就能见到效果（25.5 → 47.5 手），第二件（补距离维度）需要改网络输入或改搜索结构，不是加数据能解决的。

## 四、世界模型层：现在有的是课程，不是世界模型

区别很具体：

| | 现在有的（课程） | 世界模型该有的 |
|---|---|---|
| 世界做什么 | 冠军平台期 → 旋钮 +1 | 预测"这个策略下去会遇到什么"，主动构造 |
| 方向 | 单向变难 | 会针对冠军的弱点反制 |
| 状态 | 5 个整数 | 一个能推演的环境模型 |
| 会不会"出题" | 不会，只会调参 | 会生成新题型 |

现在的 `World.try_upgrade()` 就是"平台期加难度"，本质是**课程学习（curriculum learning）**，不是世界模型。这个区别必须说清楚，否则会高估自己做出来的东西。

---

### 4.1 第一次尝试：看冠军基因定向出题（**已做，被证伪**）

原计划（P1 第 4 条）是让世界盯着冠军基因出题：冠军 `parallel_try` 高（爱并行试），
就出「并行会污染状态」的题；冠军 `read_first` 低（不爱读码），就出「必须通读才改得对」的题。

**已实现**（`domains/code/adversarial.py`）：给 24 个 bug 模式逐个标注 counters 标签，
声明它克制冠军的哪个基因维度及方向（+ 克制偏高 / − 克制偏低），
出题权重 `= 1 + ALPHA × Σ 强度 × 偏离度`，偏离度由基因在 BOUNDS 内的归一化位置算出。
标注覆盖率 22/24（calc 的两个"一眼可见"弱题未标，走基准权重）。

**对照实验**（`domains/code/probe_adversarial.py`）：A 组 `champ=None`（随机，改造前行为）
vs B 组 `champ=<best_now.json 真实冠军基因>`（对抗），**同 seed 序列**，唯一差别是挑选策略。

| 阶段 | seed | 组数 | 随机成功率 | 对抗成功率 | 差值 |
|---|---|---|---|---|---|
| 修复前 | 201 | 30 | 0.967 | 0.900 | −0.067 |
| 修复前 | 301 | 60 | 0.950 | 0.983 | +0.033 |
| 修复前 | 401 | 50 | 0.980 | 0.980 | +0.000 |
| 修复前 | 501 | 50 | 0.860 | 0.880 | +0.020 |
| 修复前 | 601 | 50 | 0.880 | 0.860 | −0.020 |
| **修复后** | 701 | 60 | 0.967 | 0.950 | −0.017 |
| **修复后** | 801 | 60 | 0.967 | 0.983 | +0.017 |
| **总计** | | **360** | **0.9389 (338/360)** | **0.9389 (338/360)** | **+0.0000** |

**结论：对抗性出题对冠军成功率零影响。** 360 组里随机与对抗的通过数**完全相同**
（338 vs 338）。各 seed 差值在 −0.067 ~ +0.033 间摆动，方向随 seed 变，
均值 ≈ 0。这不是"效果小"，是**没有可归因于策略的效果**。

⚠️ **中途发现并修复了一个方向 bug**：counters 标注的标量解析
（`direction = -1.0 if strength >= 0 else 1.0`）把**正数判成了「克制偏低」**，
方向整个反了。修复后重跑两组，仍然零效果 —— 说明**零效果不是 bug 导致的，
是结论本身成立**。这一点很关键：差点因为 bug 而误判"修好就有效"。

**为什么没用（比结论本身更重要）**：

1. **天花板效应**：难度旋钮已拧到顶（size/depth/hidden/scaffold/resource 各 = 3，Lv15），
   冠军成功率仍有 86%~98%。在这么高的基线上，换选题策略没有可腾挪的空间。
2. **加权只在"选哪个 bug 模式"层面生效**，而题池里 24 个 bug 模式对强笔的
   难度大致相当。**对抗性出题只是在同一个（过低的）难度平面内重新洗牌，
   无法抬高天花板。**

**这条反面结果的价值**：它把 code 域的根因进一步钉死了——
不是"出题不够聪明"，而是**题池的绝对难度太低**（呼应 3.2 第三层：
「真正难住强笔的不是隐蔽性，是规模和交互」）。
所以下一步不该继续优化选题策略，而该**换题型**。

---

### 4.2 第二次尝试：换题型 —— 跨层隐含契约（**已做，仍然没难住**）

既然「在同一个题池里换挑法」无效，那就换题**本身**。新建 `domains/code/chains.py`，
题型结构改成三层：

```
core.py      底层实现，bug 在这里
service.py   上层，依赖 core 的一个**没有写进文档的不变量**
tests.py     只通过 service 断言
unit_core.py core 层单元测试
```

与旧题型的分水岭是**一条可量化验收的约束**（`chains.selftest()` 逐条检查）：

> **注入 bug 之后，core 层的单元测试必须仍然全绿。**

也就是说 core 单独看是「正确」的，只有理解了 service 隐含依赖了什么才知道它错了。
四类题（每类都验证了这组性质）：

| 题 | core 的隐含契约 | bug 之后的现象 |
|---|---|---|
| `idxsort` | 返回值严格升序 | 集合/长度/去重全对，但上层二分查不到最后一个元素 |
| `matrow` | 每次调用返回独立的新对象 | 形状、初始值全对，但写一行会串到所有行 |
| `groupord` | 保持 key **首次出现**的顺序 | 分组内容一字未变，但报表排版次序重排了 |
| `snapdiff` | 快照与活对象不再共享引用 | 键/值/长度全对，但 diff 永远判「无改动」 |

这道自检本身立刻抓出了我自己写坏的两条（记录在本章末尾的「踩坑」里），
说明把它变成可执行断言是值得的：**题型声称的性质必须能验收，不能靠嘴**。

**实验结果（n=24，同 seed 序列、同冠军基因、难度旋钮全开）：**

| 题型 | 成功率 | 平均耗时 |
|---|---|---|
| 旧题型（单文件） | 0.917 (22/24) | 380ms |
| **跨层契约题** | **1.000 (24/24)** | 388ms |
| 差值 | **+0.083** | |

**换题型反而更容易了。** 而且这还是在 `hidden=3`（**盲改**，不提供任何测试报错、
连 bug 描述都模糊成一句话）的条件下。

更关键的证据是**它给出的是最小定点修改，不是重写**：

| 题 | 原文件行数 | 补丁行数 | 占比 |
|---|---|---|---|
| idxsort | 52 | 5 | 10% |
| matrow | 48 | 6 | 12% |
| groupord | 46 | 5 | 11% |
| snapdiff | 52 | 5 | 10% |

且四次**全部命中 core（根因）**，一次都没有在 service 层打补丁绕过。

**这否定了两个廉价解释**：它不是「背答案」（结构是新写的，不在任何语料里），
也不是「暴力重写」（只动了 10% 的行，且动对了位置）。
盲改 + 跨两层 + 精准命中 —— **它确实读懂了。**

**于是根因从「题池难度低」被进一步收紧为：**

> 这套评估的难度上限不取决于 **bug 藏得多深**，
> 而取决于 **被改的模块有多大**。在 ~50 行的规模上，强笔能在一次前向里
> 把整个模块跑通并把违反契约的那一行指出来 —— 跨几层都一样。

这条结论比前一个更有力，因为它把「还能不能靠加难度救回来」这个问题，
转化成了**一个可测量的工程量**：要让强笔扛不住，得让它没法一口气 hold 住整个上下文。

**下一步的含义也随之明确了**（不再是泛泛的"加难"）：

- **规模**：把单模块撑到 300 行以上（当前 46~52 行，差一个数量级）
- **不可重写的约束**：要求补丁不得改动某段、不得退化性能、必须兼容外部调用方，
  让「重写成正确版本」这条路本身失效
- **看不见的调用方**：让真正依赖那个隐含契约的代码不在本题交付的文件里，
  而在评估器持有、笔读不到的私有测试套件中（当前 service.py 是可见的，
  所以它还能「读过一遍就推断出来」）

### 4.3 新域 hunt：把「信念」从黑箱里拽出来量（`domains/hunt/`）

4.1 和 4.2 都卡在同一个地方：**只能看胜率**。胜率涨了，说不清是学会了建模对手，
还是只是学会了某个恰好够用的动作序列。sgs 加了身份之后也一样 —— Bot 是纯行为
策略，没有地方存放「我认为座位 1 是反贼」。

所以干脆换一个能把信念**显式化**的域：**图上的追捕博弈**。

```
16 节点图（环 + 弦）
逃犯每 4 回合泄露一次位置，但其中 80% 落在**邻居**而不是本尊（噪声线索）
双方距离 <= 1 时逃犯才会察觉猎手 —— 不是单方面的隐藏信息
20 回合内走到同一节点 = 抓到
```

**三个刻意的设计**

1. 猎手维护 `belief: node -> prob`，每回合 `predict → observe` 更新。
   这就是它的世界模型，而且**可读、可算**。
2. **两个独立种群**对抗共进化。这样两侧各走各的，天然形成军备竞赛 ——
   也顺带治了 `_mini_duel` 那种「全种群塌成一个流派」的毛病。
3. **完全信息对照组**：同一对策略在猎手能直接看到真实坐标时能拿几分，
   与不完全信息的差额 = **推断的负担**。没有这个差额，就无法判断胜负变化
   到底有没有经过「推断」这一步。

还有个附带好处：**零随机**（只有策略本身的随机）。sgs 有牌运，评估预算被噪声
吃掉一大截（mean 0.147 vs 三方对称基线 0.333）。hunt 里同策略同 seed 结果确定，
而且快 —— 200 局 0.87s。

**平衡点是调出来的，不是猜的**：图上两个随机游走的相遇时间才是真正的天平。
回合数放到 60 时逃犯必死不变，压到 20 才回到 0.515（对比 §4.2 的代码域调优，
这里是同一类问题 —— **参数要在 data 上校准，不能凭直觉设**）。

#### 这里踩了个原理性的错

第一版 `observe()` 写成：

```python
self.belief[pos] = max(self.belief.get(pos, 0.0), 0.55)
```

这等价于**假设观测是精确的**。可环境里 80% 的线索落在邻居身上 ——
于是猎手在**系统性地强化错误信念**。跑了 73 代后果然一边倒崩溃：

| | gen 18 | gen 73 |
|---|---|---|
| 猎手最佳胜率 | 0.633 | **0.233** |
| 逃犯最佳胜率 | 0.810 | **1.000** |
| 信念熵（≈ln N = 完全没信息） | 2.656 | 3.029 |
| 峰值命中（随机基线 1/20 = 0.050） | 0.081 | **0.037** |

**信念比随机猜还差。**

修法是把它改成真正的贝叶斯前向更新（HMM filtering）：似然不再是一个点，
而是按「多大程度信任线索」在 tip 与它的邻居之间摊开的 kernel；这个信任度
本身作为第 11 维可进化基因 `obs_trust`。

> **教训（成型版）：在没有观测模型的情况下做信念更新，比不做还糟。**
> 凡是「部分可观测 + 要推断」的环境，第一件事就该确认似然是不是条件概率，
> 而不是一个「把它 top 到 0.55」的 hack。

### 迭代史（三轮，每轮都被数据推翻一次）

这一步花了三轮，每一轮都是「以为对了 → 数据说不对 → 再改」。按时间排：

**v1：naive 观测模型**（信念比随机还差 → 崩）

| | gen 18 | gen 73 |
|---|---|---|
| 猎手最佳 | 0.633 | **0.233** |
| 逃犯最佳 | 0.810 | **1.000** |
| 峰值命中（随机基线 1/20 = 0.050） | 0.081 | **0.037** |

**v2：贝叶斯观测 + 修了难度判据**（看着很好，但对照是假的）

改成 HMM 前向更新之后，到 gen 113 时三条信念指标一起变好：

| 指标 | 相关系数 | 开局 → 收尾 |
|---|---|---|
| 信念熵 | **−0.607** | 2.695 → 2.653 |
| 真值 NLL | **−0.582** | 2.751 → 2.682 |
| 峰值命中 | **+0.441** | 0.058 → 0.074 |

当时据此写下「推断的负担 = +0.140」。**这个数字后来被作废了** —— 详见下面 v3 的对照 bug。
（这段数字已作废：v2 里每代只 call 一次 `visible_control`，seed 序列与正式评估不同，
而** seed 决定图**，所以两边比的根本不是同一张图。）

同轮还修了一个自催化的难度 bug：`try_upgrade` 原判据是「任一方 best ≥ 0.80 就升级」，
在对抗共进化里这是把**失衡**当成了**饱和**。实测从 gen 120 起 best_e 恒 1.000，
于是每代都升级，level 从 3 一路飙到 9，猎手被压到 0.20 起不来。
改成「两侧都落在 0.45~0.85 且波动 < 0.15 才升级」+ 20 代冷却。

**v3：加补给点（目标机制）+ 同等口径的对照**（当前版本）

即使观测模型修对了，域还是往一边倒走。打轨迹一看就明白了 ——
看 seed=1 的**猎手**轨迹：`[0,1,2,3,8,3,4,3,6,3,10,9,...]`，它在 node 3 附近反复来回。
根因：**双方同速 + 逃犯有「距离 ≤ 1 就察觉」的近距感知 + 环形图没有死胡同**，
逃犯贴着跑就永远追不上。到后期连**完全信息**（看得到）的猎手抓捕率都只剩 0.092 ——
那时瓶颈早就不在推断，这个域等于白设计了。

于是给逃犯加任务：**公开位置上的 3 个补给点，集齐才算逃脱**。
它不能再靠兜圈子活下来，而猎手可以预测并守株待兔 —— **推断这才重新变成胜负手**。
猎手侧也补了第 12 维基因 `model_target`：把「对手在朝补给点走」加进自己的预测先验
（不然它的对手模型永远只是个随机游走，跟实际差得越来越远）。

同时补掉了那个伪对照：改成**同一批 pair、同一个 seed** 下跑完全信息版本
（`evaluate` 里并行多跑一遍 `visible=1`），这样两个数字才可比。

### v3 最终结果（300 代）

| 问题 | 答案 |
|---|---|
| 一边倒了吗 | **没有**。猎手 0.65~0.83、逃犯 0.62~0.81，全程对峙，没被锁死 |
| 信念学到了吗 | **方向对，幅度弱**：熵 −0.122、NLL −0.139、峰值 +0.059 |
| 推断的代价 | **+0.065**（修正值，同 seed 口径；单次 −0.17~+0.25） |
| 谁在进步 | 逃犯 +0.085、猎手 −0.060 —— **逃犯单边小幅占优** |

诚实的读法：**这个域成立，但信号弱。** 推断确实有代价（+0.065），信念三条都朝对的方向
动（只是幅度小），双方能长期对峙而不是一边倒 —— 相比 sgs/duel 已经好得多，
但离「明显看到世界模型自发成型」还有距离。

下一步该加的不是参数，是**推断的用武之地**：让补给点之间有真正的取舍（路线选择会暴露
意图），并把线索做得更有信息量。当前 +0.065 的成本说明：**看得见和看不见差别不大，
等于推断不太值钱。**

### 4.4 hunt 改成「修机—开门」（第五人格式）：推断终于值钱了

4.3 的结论是「域成立但信号弱，推断只值 0.065」。想明白原因之后，改法不是调参数，
而是**换胜利条件**：把「踩点位」（踩完就走，位置照样飘）换成「修机—通电—开门」。

#### 机制：逃脱者必须走完三步

| 阶段 | 动作 | 代价 |
|---|---|---|
| 1. 修机 | 站在解码机上**静止**若干回合 | 5 台机器，修满 3 台才通电 |
| 2. 通电 | 大门从「废的」变成「能开的」 | 通电前跑去门口等于白跑 |
| 3. 开门 | 站在大门上**静止**若干回合 | 门离机器最远，还得再跑一段 |

**关键不是「修机」这个动作，而是修机必须静止。** 4.3 里逃脱者可以一直绕圈，
位置永远飘着，猎手算不准也没关系 —— 因为「算准了」也抓不到一个一直在动的人。
静止把「移动自由」当筹码押了出去，猎手第一次有稳定的东西可推断。

#### 猎手阻止逃犯通过大门，有四层（这就是问题的答案）

1. **通电门槛**：大门在修满 3 台之前是废的。逃犯不能直接跑去开门。
2. **抓捕静止的人**：修机/开门的每一回合都不能动，这是最好的抓捕窗口。
   实测冠军对局里**逃脱者 46% 的时间钉在原地**。
3. **砸机**（`sabotage=0.22`）：猎手路过有进度的机器就砸掉 22%。
   这一条是「巡逻」存在的理由 —— 没有它，猎手只有「追」一个动作，守机永远是次优解。
4. **守门**（`camp` 基因）：通电后大门是公开信息，猎手可以直接去守。

#### 参数标定：五轮，全是实测，没有一处靠直觉

| 配置 | 猎手胜率 | 问题 |
|---|---|---|
| 16 节点 / 线索每 4 回合 / 猎手全速 | **0.948** | 逃犯被压死，域退化成「谁先看见谁赢」 |
| 加 `hunter_slow=2` | 0.832 | 有改善，仍偏猎手 |
| `hunter_slow=6` | 0.565 | 平衡了，但猎手 6 回合走一步，不像追捕 |
| 20 节点 / 线索每 10 回合 / `slow=2` | 0.745 | **选定**：猎手速度正常，靠稀线索制造不确定性 |
| 再加「修机有动静」（修机每回合泄一次位置） | 0.740 | 信念峰值命中 0.073 → **0.152** |

最后那条是被数据逼出来的：一开始修机不产生额外线索，结果**信念熵 2.94 ≈ 均匀
ln(20)=2.996**，等于什么也没推断出来 —— 线索每 10 回合才来一次，信念来不及积累。
加上「密码机在闪，修机每回合暴露一次」之后，信念才有真信息。
这条也正好对应第五人格的实质：**修机是有声音的，躲不开。**

#### 结果：冠军对冠军，推断值 22.5 个百分点

`probe_peak.py`（同批 seed、同一张图、同一对冠军策略，只换信息条件）：

| 信息条件 | 逃出 | 被抓 | 修机 | 静止时间占比 |
|---|---|---|---|---|
| 不完全信息 | 76.9% | **22.5%** | 2.99/3 台 | 46% |
| 完全信息 | 55.0% | **45.0%** | 2.97/3 台 | 56% |

**推断代价 +22.5 个百分点，比例差 z = 4.26，显著（p < 0.0001）。**

对比 4.3 的 +0.065 —— **同样的域、同样的问题，换了胜利条件之后推断值钱 3.5 倍。**

#### 这里有一个方法论上的坑，必须写下来

`analyze.py` 原来用「当轮最强猎手在完全信息下的胜率 − 它的不完全信息胜率」当推断代价，
v4 跑出来只有 **+0.062**，差点让我得出「修机也没用」的错误结论。

真因是：那个差额里，**完全信息那一侧的天花板也在塌**。看 v4 的对照列：
gen 0 时完全信息 1.000，到 gen 290 掉到 0.583 —— 逃犯进化得太强，猎手「看得见」
也只有六成胜率。两个天花板一起塌，差额自然被压平。

**这和 code 域的「评估器被打穿」是同一个病：用一个会随对手变强的指标去量「能力」。**
正确口径只能是**冠军对冠军**（同 pair、同 seed、只换信息条件），也就是 `probe_peak.py`。

#### 进化出来的行为（不是我以为的）

- **猎手**：`patrol=0`（完全不守机）、`camp=1.365/1.5`（守门拉满）、
  `stay_assume=0.536`、`obs_trust=1.0`（完全信任线索）、`chase=0.949`（猛追）。
  → 它放弃了守 5 台机器（守不过来），全押 2 扇门。
- **逃脱者**：`flee=0.276`（几乎不逃）、`greed=0.20`（不太贪）、
  `machine_far=0.26`（偏好近机）。
  → 它算出来「跑不如修」，宁愿被抓也要把进度推完。

这两条不是设计出来的，是搜出来的。**逃犯的「莽」逼着猎手从「追」转向「守门」** ——
一个 1v1 的非对称对抗里自发长出了「守尸/守门」这种战术，和真人局里的一致。

#### 还没解决的

- 逃犯仍偏强（冠军对冠军 76.9% 逃出）。当前 `need=3`、`machine_ticks=2` 对
  「跑不如修」的最优解太宽松，下一步可以抬到 `need=4` 或加「校准失败」（爆机回退）。
- `reps` 只有 3，冠军 `fit` 的方差还不小，看趋势要至少 100 代。
- 单逃脱者。真正的第五人格是 4v1，多人协作（一人被追、其他人偷修）会带来
  完全不同的策略层 —— 那是下一个域的事，不是这一版能塞进去的。

### 4.5 neuro 域：第一个由 world model 门控的课程（`domains/neuro/`）

前面几版"课程"都是冠军平台期 → 旋钮 +1，世界模型本身没有参与决策。
neuro 域第一次把预测误差变成**升级门控**：只有两个信号同时成立才升一级——

1. 冻结 holdout 判据 `saturated`（评估器已区分不出策略）；
2. one-step world model 最近 3 个 iteration 的平均 MSE < 阈值（世界已可预测）。

任一单独成立都不够：饱和但 MSE 高，说明"赢了但世界仍不可预测"（对应 gomoku 的缺维失败）；
MSE 低但没饱和，说明模型只是记住了简单世界。对手阶梯 `L0 gene1 → L1 gene2 →
L2 hard1 → L3 hard2`，升级后训练池保留旧档位，`floor_lock` 连续出现则降级。

**实测（30 iterations，8 episodes/iter，600 frames）**：

| iteration | level | holdout | world MSE | health |
|---|---|---|---|---|
| 1–3 | L0 | 0.94–1.0 | 0.098 → 0.0094 | warming_up |
| 4 | L0 | 1.0 | 0.0092 | saturated |
| 5 | **L1（升级）** | 1.0 | 0.0078 | saturated |
| 6–30 | L1 | 0.56–0.94（均值≈0.76） | 0.0059–0.0078 | ok |

升级后 holdout 立刻从 1.0 掉到 0.5–0.85，评估器重新有了梯度，且**没有再把策略练坏**
（此前无课程时 holdout 一路 1.0，PPO 实际上在优化一个失真的指标）。

**新发现：世界"可预测" ≠ 策略"已掌握"。** L1 阶段 world MSE 继续降到 0.006，
但 PPO 对 gene2 的 holdout 一直停在 0.56–0.94，没能打到饱和。模型能预测这个世界的
动力学，不代表策略能赢它。这正是门控必须同时要求 saturation 和低 MSE 的原因：
若只看 MSE，会在策略尚未掌握时提前升级；若只看 saturation，会在世界仍不可预测时升级。

**还没解决的**：

- L1 的基因（gene2）对当前"只靠近再踢"的策略可能已接近上限；要再往上，需要
  curriculum 同时改**观测/动作**（例如显式加入格挡决策），而不是只换对手。
- 当前 `hard1` 档对 BC 策略胜率仅 3%，L2 一旦触发会直接把 health 打到 `floor_lock`，
  说明梯度太陡，下一步应插一个中间档。
- world model 目前只是 one-step 观测预测；要真正"主动构造世界"，需要让它生成
  候选初始状态/障碍布局，而不是只负责门控。

## 五、踩过的坑（都是真的，不是编的）

这些坑的共同点：**代码全对，但结果不对**。每一个都值一条铁律。

| 坑 | 现象 | 根因 | 铁律 |
|---|---|---|---|
| **4 道假题** | 注入 bug 后测试照样过 | 测试写的是 bug 行为；单次调用测不出可变默认参数；fix 写反；测试与修复冲突 | 题库必须先自证：golden 必过 + 注入必败。**没自证过的题等于没题** |
| **try_upgrade 卡死** | hidden 永远停在 1，盲改永不触发 | 维度升到 1 就被移出候选池 | 上限要显式写（`MAX_LEVEL=3`），不能靠"升满了自然退出" |
| **numpy.bool_ 崩** | `json.dumps` 报 TypeError | numpy 的 bool 不是 Python bool | 跨层传值前显式转原生类型 |
| **429 误判** | 以为限流，加退避没用 | `PROMOTION_MODEL_LIMIT_REACHED` = 免费额度耗尽，硬上限 | 429 要看 body。频率问题会自己好，额度问题不会 |
| **解析器只认 ```** | 笔写对了，但解析出空 | `re.match` 必须从块头匹配；pollinations 不用 ``` 包裹 | 解析别人的输出要用 `re.search` + 无包裹兜底 |
| **缓存投毒** | 笔明明可用，程序却跳过它 | `gen_cache.json` 里存着 429 时代的 `None` | 失败结果不进缓存，或缓存带 TTL |
| **重复进程** | `state.json` 的 gen 比日志小几百 | 两个进程写同一个 `evo/` 目录 | 单实例锁（同名互斥体 / PID 文件） |

最后一条是今天刚踩的：日志里 gen 2294 和 2059 交替出现，就是因为 19:17 和 20:10 各起过一个没带 `--out-dir` 的进程，跟我 21:25 起的三个抢同一个目录。

### 第二轮新增（换题型那次）

| 坑 | 表现 | 真因 | 修法 |
|---|---|---|---|
| **自检跑不起来，误以为题全错** | `chains.selftest()` 报 4 题全 BAD，golden 也是 0 通过 | 本机 Python **没装 pytest**；正式评估其实是 `python <entry>` + 匹配 `"All tests passed"`，根本不用 pytest | 自检改成与实际评估同源的 runner |
| **声称的性质无法验收** | 「bug 后 core 单测仍绿」这条设计约束，在正式评估里**看不见**（它只看全通过与否） | 单文件入口容不下两个粒度的验收 | 给每题配独立 `unit_core.py`，单独跑；性质先要可被观测，才谈得上被保证 |
| **自己写的跨层题不合格（2/4）** | `idxsort` 注入 bug 后 core 单测跟着红、`groupord` 的 `unit_core` 用了顺序敏感断言 | 前者 bug 在重复输入下直接暴露 `len != len(set)`；后者是**我自己把跨层信息提前泄回了 core 层** | 改成「先按首次出现去重、只把最后一个元素置于末尾」；core 断言一律顺序无关 |
| **把「笔在重写」当成解释** | 一度以为跨层题全过是因为笔把整个文件重写了 | 实际补丁只占 10~12%（5~6 行），是盲改下的最小定点修改 | 先量再解释；这个假设被数据否掉了，但否定本身就成了 4.2 的主要证据 |

第三条尤其值得记：**先有可执行验收，题才真的成了那种题**。

## 七、这套东西的定位

不是"通用 AI 自我进化"，是一个**自动平衡性 / bug 探测器**：

- 给定一个规则系统（游戏、卡牌、算法题），它能自动找出**规则里的漏洞**和**最优解**
- 冠军就是那个"探针"—— 冠军能赢到什么程度，暴露了规则有多容易被利用
- 难度升级机制本身，就是"这个系统的可玩性还有多少余量"的度量

这个定位比"通用自进化"实在得多，也是三个域里唯一被数据支持的部分。

## 八、业界研究对照：我们踩的坑，业界也都在踩

联网搜了近两年的 LLM 评测与对齐文献，发现我们踩的每一个坑都有对应的业界结论，这反过来验证了我们的诊断方向：

| 我们发现的问题 | 业界对应结论 | 来源 |
|---|---|---|
| LLM 当笔时，盲改和喂报错梯度差为零 | LLM-as-judge 存在位置偏差、冗长偏差、自我增强偏差；原始分数不可信，需工程化缓解 | W&B / pls.sh / Mirascope / DataVLab |
| 评估器被打穿（冠军 99.6% 满分），进化退化 | Reward overoptimization：代理奖励一路上涨，真实质量先涨后跌；"等平台期再停"会停太晚 | OpenAI (Gao et al. 2022) / ACE Journal 2026 / arXiv 2604 |
| 组内部分维度饱和导致优化方向失效 | TaRoS：组内奖励饱和会破坏优化方向，需对饱和组件降权 | USTC / 电信 AI 等 (arXiv 2511) |
| 笔可能改测试文件刷满分 | Coding agent 经典作弊：测试不过就改测试，或找能骗过校验的捷径 | 梁良心智模型（Goodhart 定律映射到 AI） |
| 难度维度选了"bug 藏得深"但强笔不吃这套 | Goodhart 定律：指标一旦成为目标，就失真；量化目标容易被钻空子 | 梁良心智模型 |

最有价值的一条来自 arXiv 2604.13602：**奖励黑客不是某次训练的偶然失误，而是"当指标成为目标，它就不再是好指标"的结构性保证**。这解释了为什么 code 域 2300 代全是满分——不是模型强，是评估器本身已经被优化目标同化了。

所以我们的核心判断——**评估器必须比被评估者"笨"且"客观"，只看 pytest 真跑，不让 LLM 打分**——和业界的 LLM-as-judge 局限性结论完全一致：当正确答案可枚举时（如代码测试通过与否），规则检查比 LLM judge 更可靠、更便宜。

## 九、肢体碰撞：从"射程判定"到"胶囊接触"

这一轮刻意没有上 2D 平台物理，只做了一件更小的事：**让攻击由真实肢体几何判定**。
`domains/duel/limbs.py` 负责运动学与碰撞，`articulated.py` 是对局规则，`--env articulated` 切换。

### 9.1 做了什么

- 2D 矢状面正向运动学：肩/肘、髋/膝四个角度 → 手、脚、护体的坐标。角度只由
  `(state, move, phase, timer)` 决定，**不新增可变的物理状态**，所以 replay / checkpoint
  仍然只依赖 duel 原有的状态。
- 命中：攻击肢体（前臂-拳 / 胫-脚）作为胶囊，对躯干、头、双腿做 segment-segment 距离。
  选"穿透最深"的部位：头 1.35x、躯干 1.0x、腿 0.75x。
- 格挡：前臂护体胶囊必须真的挡在攻击路径上才减伤；不是"按了 BLOCK 就免伤"。
- 两方活跃肢体在空档相遇 → **clash**：两招同时取消、无人掉血。
  若任一方已够到躯干，则判定为同时命中（trade），而不是被先处理的一方取消。
- 观测 15 → 23 维（双方手/脚相对坐标）；`metrics.jsonl` 增加 `clashes` / `eval_clashes`。

### 9.2 实测

| 项目 | 结果 |
|---|---|
| 专家 vs random / gene1 | 1.0 / 1.0，平均伤害 46.5 / 27.2 |
| BC（16 局 × 120 epoch） | `bc_loss 0.0381`，vs random / gene1 均 1.0 |
| BC（8 局 × 40 epoch） | `bc_loss 0.125`，holdout 只有 0.12–0.5 |
| L0 → L1 升级 | 第 6 个 iteration 自动触发 |
| L1 holdout | 0.25–0.42（旧 1D 版是 0.76） |

两个值得记下来的点：

1. **23 维观测让 BC 所需数据变多**。同样是"靠近再踢"的一维阈值规则，15 维时 8 局 × 40 epoch
   就够；23 维（多了四个肢体端点）需要 16 局 × 120 epoch 才把 loss 压到 0.038。肢体坐标是
   策略的函数，示范分布更宽，网络需要更多样本才能拟合边界。
2. **有效射程变短了**。旧规则 punch/kick 是 1.15 / 1.50 米；肢体几何下拳约 1.07、踢约 1.28。
   于是 L1 的 gene2 在肢体版本里变成了更强的对手，holdout 从 0.76 掉到 0.25–0.42。
   这是**平衡变化，不是 PPO 崩了**——第 6 个 iteration 的下跌在换 seed、关掉 league 快照后
   都精确复现，对应的是课程从 L0 升到 L1。

### 9.3 clash 为什么在训练里一直是 0

升级后的策略是"进入 1.30 米内就踢"，而这个距离上脚已经够到躯干，按规则走 trade，
不会进入"空档相遇"分支。clash 需要双方在约 1.4–1.7 米同时出招（都没够到身体），
当前专家策略不会去那个距离。单测 `tests/test_limbs.py` 直接构造了该局面，确认 clash
会取消双方攻击且不掉血；训练指标为 0 是策略行为的结果，不是计数器坏了。

### 9.4 下一步

- 若继续沿这条线：给攻击加"高/低"两段（现在头部 1.35x 的判定几乎打不到），
  或让格挡消耗体力，肢体几何才真正影响决策，而不只是影响结算。
- 若要上 2D：先给现有关节加竖直位移与地面接触，再做平台/重力；不要一步跳到平台跳跃 +
  新观测 + 新奖励，否则物理 bug 和 RL bug 会混在一起，无法归因。

## 十、把"拳/腿"做成真实招式：速度换伤害，头部成为关键部位

上一版（第九节）虽然已经是肢体碰撞，但三个攻击的动画高度都落在躯干，头部实际上永远打不到。
这一轮按空手道/拳击的真实节奏重做了三种招式，并把头部变成能被打、也值得打的目标。

### 10.1 招式表

| 招式 | 起手/命中/后摇（帧 @60Hz） | 总时长 | 伤害 | 有效射程 | 备注 |
|---|---|---|---|---|---|
| 直拳 / oi-zuki | 4 / 3 / 7 | 14（233 ms） | 5.5（头 7.4） | 1.04 m（打头 ≤0.96） | 最快，贴身压制 |
| 前踢 / mae geri | 7 / 4 / 11 | 22（367 ms） | 8.5 | 1.29 m（躯干/腿） | 中距离 |
| 头踢 / mawashi geri | 12 / 4 / 18 | 34（567 ms） | 12.5（头 16.9） | 0.83 m | 只有贴身够得到 |

对比旧规则：拳 6/3/9（18 帧、7 伤害）、腿 11/3/16（30 帧、11 伤害）。
新直拳快 22%、伤害低 21%；新前踢快 27%、伤害低 23%；头踢慢了 13%，但打到头是 16.9。

### 10.2 头部

- 身体比例改成格斗站架：髋 0.96、躯干顶 1.40、肩 1.44、头心 1.66（半径 0.12），总高约 1.78
- 直拳的拳心高度 1.64，正好落在下巴；1.0 m 处打躯干，0.96 m 内打头
- 头踢脚心 1.70，必须进到 0.84 m 才够得到；这是"高风险高回报"的贴身招式
- 未被格挡的头击额外 +6 帧硬直（`HEAD_STUN`），并单独计数 `head_hits`
- `KICK` 仍是同一个按钮：引擎按距离自动切前踢/头踢，所以动作空间保持 6 维，策略只需学"什么时候进、什么时候踢"

### 10.3 关键发现：镜像示范会把 BC 教坏

同样的 BC 设置，示范只做"专家 vs 专家"镜像对局时：

- `bc_loss 0.029`（比之后更低），但对 gene1 holdout 只有 **0.25**，对 random 0.08
- 网络学到了用"对手肢体姿态"预测动作，而不是用距离；换一个对手就失效

改成示范对手轮换（random / gene1 / gene2 / 镜像），并且只标注被控一方：

- `bc_loss 0.083`（更高），但 holdout **0.75–0.92**、random 0.67–0.92，每局约 16 次头击
- 结论：**BC 的 loss 不是质量指标；示范分布的覆盖度才是。** 第九节里 23 维观测"需要更多数据"的判断是对的，但真正的瓶颈是示范对手单一，而不是 epoch 不够。

### 10.4 策略风格对比（25 局 × 双向）

| 专家规则 | vs random | vs gene1 | 头击数（50 局合计） |
|---|---|---|---|
| 贴身直拳（0.95 m 内出拳） | 0.78 | 0.87 | 911 |
| 中距离前踢（1.28 m 内出腿） | 1.00 | 0.96 | 73 |
| 贴身头踢（0.84 m 内出腿） | 0.30 | 0.08 | 399 |

前踢最稳，但头几乎不参与；贴身直拳胜率略低，却让头部成为主战场；头踢收益最高但也最容易在进身途中被打死。
这正是我们想要的取舍，也说明"头踢"不能靠固定阈值脚本硬写，应该交给策略在课程里学。

### 10.5 下一步

## 十一、自由二维：多给两个自由度，策略真的会用吗？

第十节把拳/腿的几何做对了，但位移仍是一维的——再强的策略也只能"前后走 + 出招"。
这一轮加了竖直轴和两个动作（跳跃、下蹲），把动作空间从 6 扩到 8、观测 23 扩到 29。
目标不是"加功能"，而是测试一个更强的假设：**自由度给够之后，进化会不会自己找到
引擎没写死的打法。**

### 11.1 新自由度怎么接进几何

不新增任何"克制规则"，只改姿势和胶囊位置：

| 输入 | 结果 | 几何原因 |
|---|---|---|
| `DUCK` | 头心 1.66 → 1.19 m | 直拳拳心 1.64、头踢脚心 1.70，从头顶掠过；前踢在髋高仍打躯干 |
| `KICK` + 下蹲 | 低扫，脚心 ~0.46 m | 低于护臂胶囊（1.2–1.4 m），格挡挡不住；只够得到腿（0.75x） |
| `KICK` + 腾空 | 飞踢，脚心升到 ~1.68 m | 起手 9 帧、9 伤害，落地后有 16 帧后摇空窗 |
| `JUMP` | 重力 9.8、起跳 2.55 m/s | 最高 0.33 m、滞空约 31 帧；空中横移只有地面的 55% |

于是"下蹲克直拳/头踢、前踢克下蹲、低扫克格挡、跳克低扫"是一个**几何推论**，
不是 if-else 表。测试里用 `closest_hurt` 的 clearance 正负号直接验证，不测行为脚本。

### 11.2 动作真的被用起来了吗

只看"能不能用"会自欺：BC 先验会让策略一直按 FWD/KICK。为此在 `metrics.jsonl` 里加了
`act_hist`（策略实际按键分布）和 `jumps/low_hits/flying_hits` 计数。

- 默认熵系数（0.01）、8 iteration：KICK 54–60%、FWD 32–43%，JUMP/DUCK 各约 1.2%
  —— 恰好等于 BC 里 10% 随机标签的噪声底，**说明新动作没被真正采用**
- 把 `--entropy-coef 0.06`、BC 缩到 25 epoch，8 iteration：熵从 0.45 涨到 0.92–1.19，
  JUMP 1.1% → **5.0%**，DUCK 0.7% → **3.5%**，PUNCH 1.6% → **5.2%**，KICK 降到 38%，
  holdout 仍维持 0.88、对 random 0.88

结论：**自由度不会自动被使用，探索强度必须跟着动作维度一起加。**
6 动作时 0.01 的熵系数够用；8 动作 + 稀疏的"下蹲/跳跃"收益需要 0.05–0.08，
否则 BC 先验把新维度永久压在噪声底。

### 11.3 为什么还没出现"意外打法"

当前对手池全是地面脚本（`Bot` 只会 0–5），它们从不惩罚"一直站着"：
前踢射程 1.29 m、出手 22 帧，稳定压过需要进到 0.84 m 的贴身选择。
所以 PPO 的最优解仍是"走到 1.1 m 一直前踢"，飞踢和低扫没有生存压力。

要看到真正的分化，下一步不是继续加动作，而是**让对手也用这些动作**：
给 `Bot` 加 freeform 档位（贴身时下蹲低扫、被逼近时跳开），并把这些档位放进课程。
到那时"跳跃/下蹲"才有被选择的理由，`act_hist` 的变化也才有解读价值。

### 11.4 本轮验证

- 52 个测试全绿（新增 16 个：跳跃弧线/落地、双击跳、空中操控、下蹲头部高度、
  低扫无视格挡、跳克低扫、飞踢打头、招式自动切换、伤害对账、确定性回放）
- `verify.py` 通过；旧 `duel` / `articulated` 行为不变（15 / 23 维观测、6 动作）
- 提交见 git log

### 11.5 下一步（按性价比排序）

1. **freeform 版脚本对手**（下蹲/跳/低扫），让新自由度有对手压力——这是当前唯一缺的环节
2. 落地硬直（跳跃变高风险）、低扫命中后短暂减速
3. 再把武器耐久度接进来（每次命中/格挡扣耐久，坏了回落到徒手）

## 十二、把椅子交给玩家：0 帧延迟到底值多少

第十一节的结论是"自由度给够了，但策略还没被逼着用"。这一轮换了一个更直接的检验：
把左边那个小人交给一个**有反应延迟的玩家**（`domains/duel/play.py --auto`），
让它和训练出来的网络打，看看胜负到底由什么决定。

### 12.1 这个"玩家"是怎么被限制的

- 只读和网络完全相同的 29 维观测；不读 `me.move` / `opp.move`
- 每 `reaction` 帧才重新决策一次（默认 12 帧 = 200 ms），中间保持上一帧意图
- 判断来袭招式只看对方脚的离地高度：>1.25 m 是头踢/飞踢（下蹲），<0.75 m 是低扫（跳）
- 会用相对速度把延迟的那一帧外推到"现在"（人不盯着 0.2 秒前的残影挥拳）

它没有任何特权，所以它找到的破绽，屏幕前的你也能看到。

### 12.2 战报（10 局 / 组，`--style pressure`）

| 反应 | 对手 random | 对手脚本 | 对手神经（8 iter） |
|---|---|---|---|
| 2 帧（33 ms） | **10/10** | — | **3/10** |
| 4 帧（67 ms） | 9/10 | — | 0/10 |
| 12 帧（200 ms） | 0/10 | 4/10 | 0/10 |

神经对手每局（约 7–9 秒）稳定打出 9–11 次前踢，命中率很高；玩家一般只能还 4–6 腿，
而且每次被击中都有 10–16 帧硬直，进攻节奏被直接掐断——**第一次交手的胜负基本决定整局**。

### 12.3 结论：它赢在帧，不在脑子

- 反应 200 ms 时，7 帧前摇的踢（117 ms）根本来不及反应，格挡按钮按下去时判定已经结算完；
  于是"反应式防守"在这个速度下是无效的，只能靠预判站位
- 把延迟压到 33 ms，同一个策略立刻从 0/10 变成 3/10，而且能 10/10 打穿 random
- 所以网络对人类的优势 ≈ 60 次/秒的决策频率 + 精确的射程边界，而不是它学会了什么人类想不到的战术
- 反过来这也说明：现在这版的"硬直—节奏"结构非常惩罚犹豫。如果想让真人玩得爽，
  要么给玩家输入加预输入缓冲，要么把受击硬直 / 后摇拉长，让"读招—惩罚"成立

### 12.4 顺手修掉的一个账本 bug

写战报时发现 `damage_dealt` 和 `events` 的攻击方被记反了：`articulated._apply_limb_hit`
收到的是**攻击者下标**（基类 `_try_hit` 收的是受害者下标），却又做了 `1 - idx`，
于是每次命中都记在挨打的人头上。奖励是对称的所以训练没暴露问题，但战报会把人打出的伤害
算到对手。已修正，并在 `test_limbs.py` 里加了"每个计数器必须归出手方"的回归断言。

### 12.5 下一步

1. 预输入缓冲（玩家按早了 3 帧内也算数），这是让真人能赢的最低成本改动
2. 受击硬直 10 → 14 帧、后摇加长，让"读招惩罚"真正成立
3. 让脚本对手也用跳跃/下蹲，把第十一节的自由度压力补上

## 十三、算力账本：先量清楚，再谈"更厉害"

前十二节一直在加东西（碰撞、招式、自由度、玩家）。这一轮不加玩法，只回答一个问题：
**在算力受限时，哪一步最该省？**

### 13.1 先看清微秒去哪了

`tools/bench.py` 在单核上把三条热路径拆开（`step` 与 `step_raw` 的差值就是观测的真实成本）：

| 环境 | step | 其中观测 | 观测占比 |
|---|---|---|---|
| duel（15 维 / 6 动作） | 8.0 µs | 3.8 µs | 48% |
| articulated（23 维） | 30.6 µs | 17.2 µs | 56% |
| freeform（29 维） | 38.1 µs | 21.3 µs | 56% |

策略前向 30.7 µs。理论上限 ≈ 14.5k 帧/s/核，但真实训练只有 **3027 帧/s**。
差的那 5 倍不在物理，而在训练循环本身。

### 13.2 账本一打开，最大的洞不是训练

给 `train.py` 每个阶段加了计时（`collect / ppo / world / eval / snapshot`），
把耗时写进单独的 `compute.jsonl`——`metrics.jsonl` 保持可复现，`resume` 等价的测试才站得住。

8 iteration、6 局 × 500 帧、单核：

| 阶段 | 累计 | 占比 |
|---|---|---|
| collect（真的在打） | 2.4 s | 30% |
| PPO 更新 | 0.3 s | 4% |
| **eval（在打分）** | **5.1 s** | **65%** |

也就是说：**每花 1 秒学习，要花 2 秒证明自己学了多少。**
评估用的是 `eval_episodes × 2 边 × 2 种对手` 完整对局，每局都可能跑满 500 帧。

### 13.3 只改调度，不动算法

加 `--eval-every N`（默认 1，行为完全不变；>1 时复用上一次的评分）。同 seed 对比：

| 配置 | 总耗时 | collect | eval | 最终 holdout |
|---|---|---|---|---|
| `--eval-every 1` | 7.9 s | 2.4 s | 5.1 s | 0.875 |
| `--eval-every 4` | **4.2 s** | 2.5 s | 1.3 s | 0.875 |

同样的技能，**少 47% 的算力**。这不是近似：训练路径没变（评估 RNG 独立），
只是不再每轮都测一次。

### 13.4 顺手做的两个小优化

- **姿态缓存**：观测和 combat 在同一帧里会重复算同一个正向运动学。按
  `(x, y, facing, state, move, phase, timer, frame//12)` 缓存后，A/B 实测
  articulated 每步 **−13%**、freeform **−8%**（freeform 的跳跃/下蹲让 key 变化更频繁，收益小些）。
- **Elo 平滑**：holdout 只有 8 局，1.0 胜率会算出 +1200 Elo 的假信号。改成加 0.5 胜 0.5 负的
  拉普拉斯先验后，同样的 1.00 变成 +492，单调且有限。

### 13.5 关于"算力最少还能变强"的三条原则

1. **采样花在悬崖边**：对手池按胜率带（50–70%）采样，而不是均匀采样。
   同样的帧数，梯度更陡——这是 PFSP 的全部意义，改的是调度，不是算力。
2. **对称性是免费的 2 倍数据**：小人是左右镜像对称的，镜像 obs + 镜像动作可以近乎零成本
   把数据翻倍；现在还没做。
3. **压缩动作空间比加动作空间更划算**：8 个按钮 × 每帧的搜索空间，绝大多数组合毫无意义。
   先学 4–6 个"技能宏"（贴身前踢、外切低扫、后撤反打），再学"何时调用"，
   有效搜索空间能降一个数量级。

### 13.6 下一步

按性价比：镜像增广（几小时，~2× 数据）→ PFSP 对手采样（纯调度）→ 技能宏动作（要重训）
→ 最后才是新物理（hitstop、pushbox、防御槽）。

## 十四、替身术与隐空间：给"自由度"加一条资源约束

这一轮来自三个类比：大模型把一切压进高维向量、世界模型在虚拟空间里预测物理、
火影忍者格斗的替身术。落地成两件互不依赖的事。

### 14.1 替身术（替身，action 8）

| 参数 | 值 | 理由 |
|---|---|---|
| 查克拉上限 / 回复 | 100 / 0.6 每帧 | 满约 2.8 秒，比一局（约 450 帧）短 |
| 单次消耗 | 40 | 两次替身就见底，必须和进攻抢资源 |
| 起手无敌 | 4 帧 | 能躲 4 帧内落下的攻击，躲不开 12 帧起手的头踢，除非预判 |
| 瞬移位置 | 对手身后 0.9 m | 把人换到背后，攻守同时反转 |
| 落地硬直 | 6 帧 | 可以被反打，替身不是无责任脱出 |
| 冷却 | 72 帧（1.2 s） | 防止连按 |
| 可用状态 | 站立/走/格挡/下蹲/空中/**受击硬直** | 但**不能取消自己的出招** |

关键设计：替身只有在`受击硬直`里按才像"逃连段"，但引擎里受击后攻方通常也在后摇，
所以它实际承担的是**换位**与**躲慢招**。实测每局 3–6 次，其中 0.2–1.0 次真的在无敌帧里
让对手的攻击落空（`sub_avoided`）——不是每一次都救命，这正是资源约束的意义。

### 14.2 隐空间世界模型（`selfplay/nn/latent.py`）

原来的 `WorldModel` 直接预测 33 维观测。现在改成：

```
obs(33) --encoder--> z(8) --predictor(+action)--> z'(8) --decoder--> obs'(33)
```

三个训练信号分开：重建损失训练 encoder+decoder（防止塌缩），隐空间 MSE 训练 predictor
（目标 stop-gradient），encoder 不接收预测梯度。没有 BPTT，没有想象 rollout——这一轮先把
"压缩"这件事做对，再谈用压缩后的空间做规划。

8 iteration 实测（`--env freeform --latent-world`，6 局 × 420 帧）：

| | iter 1 | iter 4 | iter 8 |
|---|---|---|---|
| 隐空间 MSE（8 维） | 0.0813 | 0.0097 | **0.0067** |
| 重建 MSE（33 维） | 0.1124 | 0.0182 | **0.0170** |

12 倍的预测误差下降，说明 8 维确实装下了这套格斗的大部分动力学。注意两个数的单位不同，
不能直接和 obs 空间的 `world_mse` 比大小，只能各自看趋势。

### 14.3 自由度真的被用起来了吗

同一轮里的按键分布（策略实际按下的比例）：

| iteration | KICK | SUB | JUMP | DUCK | 熵 |
|---|---|---|---|---|---|
| 1 | 74% | 1.2% | 1.2% | 1.0% | 0.30 |
| 4 | 56% | 2.2% | 2.1% | 2.1% | 0.86 |
| 8 | **42%** | **5.0%** | **6.0%** | **4.8%** | 1.18 |

替身的使用量随熵上升而单调上升，和上一轮 jump/duck 的结论一致：**动作空间变大以后，
探索强度不跟着加，新动作就永远停在噪声底**。holdout 在第 5 轮从 1.00 掉到 0.88，
是课程换了对手（L0→L1），不是策略退化。

一个反直觉的细节：评估端 `eval_subs` 一直是 0。训练时用采样（替身占 5%），
评估时用 argmax，5% 的概率永远赢不过 KICK，所以贪心策略一次都不替身。
也就是说"策略分布里会替身"和"贪心策略会替身"是两回事——如果只盯着评估指标，
会误以为替身根本没生效。

### 14.4 关于"压缩到极致就通用"

隐空间的维度和观测尺寸解耦了：同一个 8 维瓶颈可以接 15 维（1D）、23 维（肢体）、
33 维（自由二维）输入，未来接 3D 也只是换 encoder 的第一层。重建 MSE 和隐空间 MSE
可以跨场地比较，这是"换地图/换维度还能复用"的第一步。

但要说清楚：**压缩本身不产生智能**。真正的通用性来自"在隐空间里做预测和规划"，
这一轮只完成了压缩 + 预测，还没有让策略在隐空间里想象。下一步才是用隐空间误差做
惊奇奖励、用 latent rollout 训练策略。

### 14.5 测试

新增 7 个替身/查克拉用例和 5 个隐空间用例（形状、收敛、状态往返、误差对账），
全套 **73 个测试**通过；`verify.py` 通过。

## 十五、把大模型的训练配方叠上来：哪些有用，哪些反而有害

一次把 LLM 训练里"默认就该有"的东西全加上，然后做消融——因为这个环境的预算很小，
"堆料"和"变强"不是一回事，必须一项项证明。

### 15.1 加了什么

| 组件 | 大模型里的原型 | 实现 |
|---|---|---|
| AdamW | 解耦权重衰减 | 只衰减权重矩阵，bias 不动 |
| Warmup + cosine | 学习率调度 | 线性升温 2–3 轮，余弦退到 10% |
| KL 锚 | RLHF 的 `β·KL(π‖π_ref)` | rollout 时算 ref log-prob，损失里加 `β(logp − ref_logp)` |
| EMA / 模型汤 | shadow weights | 影子权重单独评测，指标 `ema_win` |
| 拒绝采样微调 | STaR / RFT | 每轮保留收益前 25% 的轨迹，再跑 1 个 epoch 监督学习 |
| 镜像增广 | 数据增强 | 左右镜像 BC 示范（场地对称、动作是"朝对手"的相对语义） |
| 熵退火 | 采样温度衰减 | 熵系数从 0.05 线性降到 0.015 |

### 15.2 实验设置

freeform 环境，`--holdout-level 1` 把评估对手钉死（否则课程会在中途换敌人，A/B 不可比），
12 iteration、每轮 6 局、评估 8 局、`--entropy-coef 0.05`，多 seed 取均值。

| 配置 | 最终 holdout 胜率 | 熵 | 替身使用 |
|---|---|---|---|
| baseline（纯 PPO+BC） | 0.402 ± 0.055 (n=8) | 1.14 | 2.9% |
| **优化器四件套**（AdamW+调度+EMA+镜像） | **0.473 ± 0.051 (n=8)** | 0.72 | 3.0% |
| 全量 LLM 栈（+KL 锚 +RFT +熵退火） | 0.229 ± 0.063 (n=3) | 0.56 | 1.4% |
| 全量栈但关掉熵退火 | 0.271 ± 0.028 (n=3) | 0.64 | 1.3% |

### 15.3 结论

1. **优化器/数据侧的 buff 有小幅正收益**（+7 个百分点，约 1 个标准误），方向一致：
   权重衰减让 param norm 稳定在 16.8（baseline 15.3），clip fraction 从 0.063 降到 0.038。
2. **KL 锚 + 拒绝采样在这里是有害的**，比优化器版低 24 个百分点。原因很清楚：
   - 这两项都在把策略往 BC 先验上"磨尖"，熵从 1.14 压到 0.56；
   - 新动作的使用率同时掉回噪声底（替身 2.9%→1.4%，跳跃 5.1%→1.3%）；
   - 上一轮（第十一节、十四节）已经证明这个环境恰恰需要**更高的**熵，新招式才会被探索到。
   也就是说，LLM 需要 KL 锚是因为它要在巨大动作空间里防止跑偏；这里动作空间只有 9 个，
   先验本身就是最强策略，锚住它等于禁止探索。
3. **EMA 没有赢过实时策略**（0.385 vs 0.473）。EMA 在 LLM 里好用是因为权重更新次数极多；
   这里每轮只有几百次更新，影子权重始终落后半个迭代。
4. `--holdout-level` 是这轮顺手加的关键工具：没有它，课程会在你进步时换敌人，
   任何 A/B 都会被"目标移动"污染。之前第 6 轮胜率骤降的误判（第十节）就是这个坑。

### 15.4 一个必须记的坑

预设开关第一次实现时是"值 ≤ 0 就填默认值"，结果 `--llm-stack --kl-coef 0` **被静默覆盖回 0.02**，
消融跑出来的 "opt" 和 "stack" 一模一样。改成"默认值一律 None，显式 0 表示关闭"后才正确。
任何带预设的 CLI 都得给"关闭"留一个可表达的输入，否则消融本身就是假的。

### 15.5 测试

新增 14 个用例（LR 调度端点/单调性、EMA 收敛与状态往返、拒绝采样的 top-k 与容量、
镜像对合性与索引、AdamW 只衰减权重），全套 **87 个测试**通过。

## 十六、零数据自进化：不给它数据，让它自己选对手

用户的诉求是"不用给它数据，让它自己训练、自己选择最优的"。于是把三条外部依赖全部拔掉：

* 没有 BC 示范（`--selfevolve` 默认 `bc_episodes=0`）；
* 没有手写的对手阶梯（`CURRICULUM_LEVELS` 不参与）；
* 没有 KL 先验（锚在随机初始化上没有意义）。

### 16.1 留下什么

对手池 `domains/neuro/selfevolve.py` 只含三类，全部由智能体自己产生：

| 来源 | 生成方式 |
|---|---|
| `random` | 随机动作，作为永久的"不会输得太惨"的锚 |
| `selfN` | 每若干轮冻结一份当前策略，AlphaZero 式的镜像自博弈 |
| `evoN` | 从"胜率最接近 50%"的那个对手的基因做高斯变异；没有前沿时用随机基因 |

每个对手只有一条 EMA 胜率（α=0.25）和 `games`，由 `record()` 独占更新。
采样有三种规则：`pfsp`（∝ `(1−win)^β`）、`progress`（∝ |Δwin|）、`uniform`（对照）。

### 16.2 实验 A：谁该拿到帧

freeform，45 轮 × 6 局，`--holdout-level 0` 固定评估，2 seeds：

| 采样 | 20 轮胜率 | 45 轮胜率 |
|---|---|---|
| uniform | 0.417 ± 0.136 (6 seeds) | 0.00 / 0.29 |
| pfsp（经典） | 0.111 ± 0.073 | — |
| pfsp + 冷启动下限 | 0.250 ± 0.250 | **0.71 / 0.92** |
| progress | 0.139 ± 0.028 | — |

两个现象都值得记：

1. **短周期里 PFSP 是负收益**。它把权重 ∝ (1−win)^2 压在"打不过的对手"上，
   冷启动时等于把全部帧喂给一堵墙；uniform 反而先学会基础动作。
   加 `--pfsp-floor 0.10`（从没赢过的对手权重 ×0.15）后从 0.11 抬到 0.25，
   长周期再反超 uniform（0.71/0.92 vs 0.00/0.29）。
2. **曲线是台阶式的**：PFSP+floor 的前 30 多轮几乎全是 0，然后在 4 轮内跳到 0.9。
   这不是曲线平滑的"渐进学习"，是能力阈值型学习——先攒够能赢一个对手的最小能力，
   然后整条对手池同时变得可赢。这类曲线的 checkpoint 选择比"最高分"更值得研究。

### 16.3 实验 B：参数量到底吃多少

同一任务、同样 12 轮、`--hidden` 扫描（各 3 seeds）：

| hidden | 参数量（相对） | 最终胜率 |
|---|---|---|
| 16 | 0.48× | 0.778 ± 0.056 |
| **32** | **1.0×** | **0.917 ± 0.048** |
| 64 | 1.9× | 0.889 ± 0.028 |
| 128 | 3.8× | 0.861 ± 0.028 |

**32 就饱和，再大只会更慢、更容易过拟合先验。** 这正好回答"参数量是不是关键"：
在这个 3 万帧的数据量上，瓶颈是数据与探索，不是容量。把 hidden 从 64 提到 128，
参数量翻倍，胜率反而降 3 个点。换句话说，**没有数据支撑的参数量是纯开销**。

### 16.4 结论

* 零数据自进化**能跑起来**：45 轮、每轮 6 局（约 1.6 万帧）后能到 0.9 胜率；
* 但它**方差大、冷启动慢**，且对采样规则敏感——PFSP 的前提是"已经能赢一部分"，
  不满足时必须是 uniform 或加 competence floor；
* 自进化解决的是"不需要人给数据"，不是"少算力"。要少算力，仍要靠第十五节的结论：
  别把预算花在每轮评估和改不动的正则项上。

### 16.5 测试

新增 19 个用例（EMA 更新、三种权重、前沿选择、淘汰与容量、基因边界/变异、
state 往返、以及一个"跑 3 轮、无 BC、池子自己长大"的集成测试），全套 **106 个测试**通过。

## 十七、四件"让结论站得住"的事：统计、隐表征、权重要素、想象

这一轮不加招式、不加地图，只补四件让前面所有结论可信的东西。每件都配了对照组。

### 17.1 评估：先承认 6 局测不出 5 个点

6 局评估的标准误约 ±0.20。此前所有"提升 3–7 点"的结论都在一个标准差内。
现在：

* `_evaluate` 返回逐局结果，`metrics.jsonl` 每轮写 `holdout_ci_low/high` 和
  `holdout_outcomes`；
* `selfplay/core/stats.py` 提供 bootstrap 区间、配对差、Wilson 区间、`required_games`；
* `tools/ab.py` 按 iteration 配对两个 run，输出 Δ 的 95% 区间。

评估套件本来就是固定的（seeds 2000..，双向），所以两个 run 的第 i 轮是**真配对**，
不是两次独立抽样。这条改动没有增加任何训练成本，只是把"我觉得更好"换成了"区间不跨 0"。

### 17.2 隐表征：8 维够不够

把策略输入从 33 维手工特征换成学到的 8 维隐向量（编码器在 BC/随机数据上自监督预训练后冻结）。

| 配置 | 逐 seed 最终胜率 | 均值 |
|---|---|---|
| 33 维手工坐标 | 0.812 / 0.812 / 0.938 | **0.854 ± 0.042** |
| 8 维学到的坐标 | 0.688 / 0.812 / 0.438 | 0.646 ± 0.110 |

**均值低 21 个点，但区间仍然很宽。** 用 `tools/ab.py` 对单个 seed 做逐轮配对，
甚至给出 `Δ = -0.037, CI [-0.104, +0.033] -> tie`：8 局/轮的评估分辨率还不足以
在单个种子上分辨这 20 点。三组种子同向、且方差变大，只能说明"很可能更差"，
不能写成定论。
真正的结论不是"隐表征没用"，而是"8 维太窄，而且这 33 个数里有相当多
是免费的人写先验"（距离、朝向、硬直剩余帧都是人替它算好的）。要通用，得让它学到
同样多的信息，而不是假设 8 个数能装下。

顺带修掉一个会直接崩掉的 bug：`--latent-policy` 下快照对手仍按 33 维吃观测，
第 4 轮左右必然 `matmul` 维度报错。快照现在带上同一个编码器。

### 17.3 好奇心：它学会的是瞬移，不是探索

用隐空间预测误差当内在奖励（`--surprise-coef`），只奖励高于自己平均误差的部分：

| 配置 | 逐 seed 最终胜率 | 替身使用 | 踢占比 |
|---|---|---|---|
| 8 维策略 | 0.688 / 0.812 / 0.438 | 9.4% | 32% |
| 8 维策略 + 好奇心 | 0.938 / 0.375 / 0.125 | **14.4%** | **39%** |

行为分布直接说明了机制：**替身术是状态空间里的不连续跳变，预测误差最大**，
所以好奇心把策略练成了"不停瞬移"。奖励没有指向胜利，它指向"模型没想到的地方"。
两个种子的胜率因此塌到 0.375 / 0.125（第三个种子恰好也高，不能掩盖趋势）。
这一版的好奇心是**反向**的，除非把 bonus 限制在非瞬移状态，或改用 RND 式固定随机网络。

### 17.4 想象：有效，但样本少

用奖励头 + 2 步隐空间 rollout 生成额外训练步（Dyna）：

| 配置 | 最终胜率 | 世界模型 MSE |
|---|---|---|
| 无想象（n=2） | 0.854 / 0.854 | 0.0103 |
| 想象 2 步（n=2） | **0.938 / 0.938** | **0.0072** |

方向对：模型帧补上了稀疏奖励的空档。但 2 个种子、8 局评估，只能算"值得继续测"，
不能算结论。

### 17.5 权重要素：选不动，因为尺子太粗

PBT（克隆 → 按张量尺度加噪 → 用固定评估打分 → 留前一半 → 变异补位）跑起来了，
但每一代的 `pbt_best == pbt_mean`：**所有成员分数完全一样**。3 局评估的分辨率
低于变异强度，选择压力为零，所以 PBT 在 15 轮里只采纳了 1 次冠军。

这不是 PBT 的错，是尺子的问题：锦标赛选择要么用连续 fitness（比如平均剩余血量、
命中率、对局长度），要么把每代评估提到 20 局以上。用二值胜负 + 3 局，选择就是随机的。

### 17.6 结论

* 评估区间现在是硬性产出，`tools/ab.py` 是唯一允许下结论的方式；
* **人写坐标仍是最强的免费午餐**：想用学到的表征替代它，8 维不够，且要付掉 20 个点；
* 好奇心在这个奖励结构下是害的，它奖励的是"模型没预测到"，不是"赢"；
* 想象与 PBT 都需要更细的评估分辨率才能证明自己。

测试：新增 22 个（统计、PBT、隐空间奖励头、冻结编码器、想象步数、A/B 工具），
全套 **128 个测试**通过。

## 十八、把"尺子"换细之后：连续适应度、隐维度扫描、RND 好奇心

上一轮的三条待办都做完了。这一轮的共同点是：**不改环境，只改"怎么打分"和"表征收多宽"**，
然后用配对区间判断这些改法有没有用。

协议固定：`--env freeform`、15 轮、每轮 5 局、220 帧、8 局评估（固定 seeds 2000..、双向）、
`--no-curriculum --holdout-level 0`、3 个 seed（7/17/27）。所有对比都是同 seed 同评估套件。

### 18.1 连续适应度：先让选择有东西可选

胜负是二值的。评估一旦饱和到 0 或 1，`pbt_best == pbt_mean`，选择压力归零——
这不是 PBT 的实现问题，是尺子只有两格。新增：

* `_play` / `_evaluate` 记录 **血量差** `margin = (me.hp - other.hp) / 100`；
* `metrics.jsonl` 写 `train_margin`、`holdout_margin` 及 bootstrap 区间；
* `--fitness {win,margin}` 决定 PBT 用哪个信号打分。

同一批 PBT 配置（4 成员、每代 4 局、每 3 轮一代、12 轮、3 seeds）的每代
`best - mean`：

| fitness | seed 7 | seed 17 | seed 27 | 采纳次数 |
|---|---|---|---|---|
| win | 0, 0, 0, 0 | 0, .094, .078, .094 | .062, 0, 0, .031 | 3 / 3 / 3 |
| margin | .046, .013, .025, .018 | .012, .008, .011, .012 | .012, .003, .008, .016 | 4 / 1 / 3 |

**连续信号确实消除了"全员同分"**：margin 的 12 代全部有非零差距，win 有 5 代完全为零。
但这只证明"尺子变细了"，没证明"进化变强"：12 轮太短，最终胜率
（1.000 / .875 / .688）并没有超过 win 版（1.000 / .938 / .875）。
结论应写成：**先解决可分辨性，样本量的问题留给更长的 run**。

### 18.2 隐维度扫描：8 维太窄，24 维几乎追平手工坐标

上一轮只知道"8 维比 33 维手工坐标低 21 点"，这一轮把宽度当成自变量扫了一遍：

| 策略输入 | 逐 seed 最终胜率 | 均值 | 血量差 | 世界模型 MSE |
|---|---|---|---|---|
| 33 维手工坐标 | .875 / .875 / 1.000 | **.917 ± .072** | +.168 | .0088 |
| 8 维隐向量 | .625 / .250 / .625 | .500 ± .217 | -.058 | .0064 |
| 16 维隐向量 | .125 / .750 / 1.000 | .625 ± .451 | -.002 | .0081 |
| **24 维隐向量** | **.875 / .875 / .875** | **.875 ± .000** | **+.206** | .0071 |
| 32 维隐向量 | .750 / .750 / .750 | .750 ± .000 | +.145 | .0073 |

两个可复现的事实：

1. **8 维确实装不下**。不是"隐表征没用"，是瓶颈宽度不够。24 维把 21 点差距
   收回到 4 点，血量差甚至略高于手工坐标。
2. **宽度不是单调收益**。32 维比 24 维低 12.5 点，且三个 seed 完全同分——
   多半还是优化/初始化方差，而不是"32 维更差"的物理结论；但至少可以说
   **24 附近是这个任务在当前数据量下的合理宽度**，再往上加维度的收益不可靠。

顺带说明：16 维那行 .125 的种子不是 bug，是隐空间训练本身的方差。三个种子
差距 87 个点，正好说明"单个 seed 的结论不可信"这条老规矩。

### 18.3 RND 好奇心：不再奖励瞬移，但也没换来胜率

WM 好奇心的问题是方向错误：它奖励"模型没预测到"，而替身术是状态空间里
最大的不连续，于是策略学会不停瞬移（上一轮 0.938 / .375 / .125）。

新增 `selfplay/nn/rnd.py`：固定随机目标网络 + 可训练预测器，
novelty = 预测器对**当前状态**的误差。目标永不更新，所以"是否熟悉"只能随
访问次数下降，一帧之后的状态不会被当成新大陆。`--surprise-mode {wm,rnd,none}`。

| 8 维策略 + 系数 0.5 | 逐 seed 胜率 | 均值 | 替身占比 | 踢占比 |
|---|---|---|---|---|
| 无好奇心 | .625 / .250 / .625 | .500 ± .217 | 1.4% | 55.7% |
| WM 好奇心 | .250 / .812 / **.000** | .354 ± .416 | 2.0% | 50.4% |
| RND 好奇心 | .625 / .375 / .750 | **.583 ± .191** | 2.3% | 49.2% |

逐轮配对（同 seed、同评估套件，`tools/ab.py`）：

| seed | RND - 无好奇心 | 95% CI | 判定 |
|---|---|---|---|
| 7 | -.075 | [-.183, +.017] | tie |
| 17 | -.117 | [-.179, -.054] | **更差** |
| 27 | +.067 | [+.008, +.125] | **更好** |

**RND 不是"更好"，是"不再崩"**：WM 版有一个 seed 直接掉到 0，RND 最差 0.375；
但三个 seed 的方向互相抵消，均值 +8 点仍在噪声内。替身占比也没有像 WM 那样抬升。
这条结论的价值是**否定性的**：好奇心要先用对方向（RND 而非世界模型误差），
但"状态新不新鲜"本身仍然不等于"离赢更近"。下一轮若还要碰好奇心，
应该把它和胜负信号做正交化（只奖励"没见过的状态 × 赢的回合"），而不是继续调系数。

### 18.4 结论

* 评估器的问题可以分成两层：**分辨率**（margin 解决了"全员同分"）和
  **对齐**（margin 更高不等于赢更多，需要更长 run 验证）；
* 隐表征的瓶颈是**宽度**而非"有没有用"：8 维亏 21 点，24 维只亏 4 点；
* 好奇心的瓶颈是**方向**：WM 误差会把策略教成瞬移，RND 修掉了这个病，
  但没有把它变成胜率。内在奖励必须和任务奖励对齐，否则只是更精致的噪声。

测试：新增 6 个（RND 收敛/目标冻结/state 往返、margin 指标、RND 集成、
margin 版 PBT），全套 **134 个测试**通过。

## 十九、给格斗小人装一套情绪，以及 3D 的第一块地基

这一轮先横向看了同类格斗游戏的设计，再决定"往上扩"扩什么，最后把情绪做成可测的状态，
而不是一句文案。

### 19.1 同类游戏里真正被反复验证的机制

| 机制 | 出处 | 为什么值得抄 |
|---|---|---|
| footsies / 单招博弈 | [FOOTSIES](https://fightinggameguide.com/footsiesgame.html) | 只有一个攻击键、没有跳蹲，胜负仍由距离和出招时机决定——说明"帧数据 + 距离"比动作数量重要 |
| 防御槽 / chip / 破防 | [MK1 Defense](https://srk.shib.live/w/Mortal_Kombat_1/Defense) | 格挡必须有成本，否则最优策略是永久龟缩 |
| counter-hit / 帧优势 | [Combat Design](https://skillmd.ai/skills/combat-design/) | 打中对手起手/收招应当比打中中立姿态更赚，才会出现"读招" |
| sidestep / 侧移让招挥空 | [Tekken Sidestep](https://wavu.wiki/t/Sidestep) | 3D 格斗的定义性机制：距离不变，横向一步就能让整条攻击线落空 |
| 取消 / 佯攻 | [SF6 C. Viper 调整](https://www.streetfighter.com/6/buckler/fr/battle_change/20260317/cviper) | 让"起手"本身变成可博弈的信息，而不是承诺 |

这一轮落地了前两条里最便宜的两个：**防御槽 + 破防硬直**、**counter-hit 1.35x + 8 帧硬直**。
没有加动作数量（9 个已经够 PPO 在 15 轮内学不完），加的是"同一个动作在不同时机价值不同"。

### 19.2 情绪函数：四个漏积分量 + 情绪传染

`domains/duel/affect.py`，`--emotion` 打开。每个角色 4 个 [0,1] 状态：
冷静 `composure`、恐惧 `fear`、愤怒 `anger`、气势 `momentum`。

更新式（每帧）：

```
x <- decay * x + event + contagion + danger(hp)
```

* 事件：命中 / 被打 / 挥空 / 破防（幅度与伤害、是否爆头有关）；
* 情绪传染：`fear += 0.004 * opp.anger`，`momentum -= 0.003 * opp.momentum`；
* 低血量：`hp < 35%` 时按比例持续加恐惧、扣冷静；
* 衰减：恐惧 0.995、愤怒 0.992、气势 0.985（按 60 Hz 算，3–5 秒后仍有残留，
  否则"情绪"只是当前帧的另一种写法）。

它不是奖励，而是**观测**：双方各 4 维追加到 35 维观测上（共 43 维）。这样只看当前帧的
MLP 也能拥有"这回合挨了多少打、连中了几个、对手是不是打疯了"的记忆。
另外低冷静会让防御槽多掉最多 60%——恐惧真的会让手抖。

**实测 1：15 轮 × 3 seeds，情绪 vs 无情绪（其余完全相同，含防御槽）**

| | 逐 seed 胜率 | 均值 | 血量差 | counters/局 |
|---|---|---|---|---|
| 无情绪 | .500 / .500 / .500 | .500 ± .000 | +.006 | 4.20 |
| 情绪 | .500 / .500 / .375 | .458 ± .072 | +.041 | 4.13 |

15 轮内没有胜率收益，血量差略高但仍在噪声内。回合末情绪均值：
冷静 .766、恐惧 .068、愤怒 .082、气势 .200——说明状态确实在动，不是常零。

**实测 2：情绪输入是否真的改变决策？** 取 seed 7 的情绪策略，固定输入做探测
（其余观测来自真实对局，只改 p0 的情绪向量，确定性动作）：

| 固定情绪 | KICK | FWD | 其余 |
|---|---|---|---|
| 冷静 (.95/.02/.02/.15) | 93% | 7% | 0% |
| 恐惧 (.25/.85/.65/.05) | 23% | 77% | 0% |

结论要分两层：

1. **情绪维度是"活"的**：同一观测下换情绪输入，动作分布从 93% 踢变成 77% 前压。
   策略确实在读这 4 维，不是被忽略的填充。
2. **学到的映射还不像人**：恐惧时它选择前压而不是拉开/格挡。原因是训练分布里
   恐惧很少到 0.85（回合末均值只有 0.068），这是分布外输入。要让它"像人"，
   下一轮应该把情绪做成非对称采样（故意让对手压着打），而不是继续调公式常数。

另：15 轮里 `guard_breaks = 0`、`BLOCK` 占比约 1.8%。防御槽机制本身有单测覆盖
（连续挡刀会破防），但当前策略几乎不格挡，所以它在对局中还没被真正激活。
这比"加了个机制"更重要：**机制存在 ≠ 机制被使用**，指标必须分开报告。

### 19.3 走向 3D 的第一块地基

2D→3D 不是"多一个坐标"，而是攻击线可以被侧移让开。`domains/duel/space3d.py`
先落地了不依赖环境的几何核心（全部有测试，暂不在热路径）：

* `Vec3`、`point_segment_distance`、`segment_segment_distance`（Ericson RTCD 5.1.9）；
* `capsule_distance` / `capsules_overlap`（线段距离减两半径）；
* `sidestep_clears(attacker_z, defender_z)`——3D 里才可能为 `True` 的谓词；
* `isometric` / `orthographic`：把 3D 状态投回现有字符画，调试器不用重写。

路线：**几何（已完成）→ z 轴侧移动作 + z 观测 → 3D 肢体胶囊姿态 → 摄像机/渲染**。
下一步很小：给 `Fighter` 加 `z/vz`，动作加 `SIDESTEP`，把 `_guard_hit` 的距离判定换成

### 19.4 结论

* 机制扩张应该选"同一动作在不同时机价值不同"的规则（防御槽、counter-hit），
  而不是继续加按钮；
* 情绪作为观测能提供跨帧记忆，且已被证明会被策略读取，但 15 轮内不产生胜率；
  下一步要控制训练分布，而不是调公式；
* 3D 先做几何与谓词，再动动作空间，能把风险隔离在一个模块里。
