# 研究发现：自进化 / 世界模型这条路，走通到哪一步

> 记录时间：2026-10-29 晚。三个域都在跑，数字会变；结论除非被新数据推翻，否则不改。

---

## 一、先给结论

分成三层说，因为三层的结果完全不一样：

| 层 | 问题 | 结论 | 证据 |
|---|---|---|---|
| **机制层** | 自博弈 + 遗传搜索 + 难度自迭代，这套东西转得起来吗？ | ✅ **转起来了** | 三个域都在无人工干预下连续跑了几十到几千代，难度真的升了，冠军真的变了 |
| **评估层** | 评估器能不能持续给出有效梯度？ | ⚠️ **一半崩了** | code 域冠军 99.6% 满分（3603/3617），梯度归零；sgs 域零满分，梯度健康 |
| **世界模型层** | 这算不算"世界模型"？ | ❌ **还不算** | 现在有的是**课程（curriculum）**：5 个难度旋钮 + 平台期触发升级。世界不会预测"你这么做会发生什么"，只会调参 |

一句话：**自进化这条路走得通，但它的天花板不在搜索算法，在评估器。**

## 二、机制层：确实转起来了

### 2.1 三个域的三种命运

同一套骨架，换三个世界，跑出三种完全不同的结果——这本身就说明机制不是"写死能过"的：

**duel 域（格斗）—— 收敛成功，但趋同**

- fit 从 0.508 单调爬到 1.126，最高 1.139
- 61 代后代际漂移已经把「反击流」推到 20/25 的绝对多数
- 冠军长这样：`aggr=0.976 guard=0.982 kick=0.036 dist=0.89 react=1`
  → 读作「贴身猛攻 / 见招就挡 / 几乎只用拳 / 保持 0.89m / 反应 1 帧」
- **这是真收敛**：格挡偏置顶到 0.98、踢几乎弃用，符合"拳的每秒伤害更高"这条规则事实（拳 23.3 vs 踢 22.0）
- **但也是问题**：20/25 都是反击流，种群多样性 0.207 在往下走。再跑下去会锁死在局部最优

**sgs 域（卡牌）—— 梯度健康，一直在挣扎**

- fit 0.573~0.896 之间波动，949 代**没有一次满分**
- mean 稳定在 0.479 左右，div 0.16~0.19
- 难度 Lv4 全开（初始手牌/杀密度/桃密度/起始血量）
- **这才是健康的自博弈**：冠军始终够不着天花板，选择压力一直存在

**code 域（编程）—— 被打穿了**

- 2302 代，**3603/3617 条冠军记录 fit=1.000**（99.6%）
- 难度 Lv5 五维全开也一样满分
- 冠军基因退化到极端值：`retry_cap=8 parallel_try=5 scaffold=0.999`
- 这不是"模型很强"，是**评估器坏了**——详见下一节

### 2.2 难度自迭代真的会触发

不是每代都升，是等 EMA 进平台期才升：

```python
tail = hist[-10:]
spread = max(tail) - min(tail)
if spread >= 0.01: return False   # 还在涨，不升
# 平台了 → 挑一个维度 +1（优先开还没开过的维度）
```

**后来补了一条更关键的判据：冠军饱和。**

最近 10 代里 ≥8 代 `best_fit ≥ 0.999` 也会触发升级。补这条的原因：只用 EMA spread 会漏判。code 域 best 几乎恒为 1.000，但偶尔夹一两代掉到 0.9x，EMA 就在 0.95~1.00 之间抖，spread 永远 > 0.01，于是 2300 代一次都没升过——不是没平台，是判据只盯着"均值稳不稳"，没盯"冠军是不是已经打穿评估器"。

实测触发记录（`data/*_levels.jsonl`，旧数据）：

```
code: gen 9  → size=1 scaffold=1
      gen 10 → +hidden=1（开始盲改）
      gen 11 → +resource=1
      gen 12 → +depth=1  ⇒ Lv5 全开
sgs:  gen 51 → hand=1 hp=1
      gen 52 → +tao=1
      gen 53 → +sha=1    ⇒ Lv4 全开
```

机制是活的。**问题是升到顶之后没有下一层了**——这是设计缺口，见第四节。

## 三、评估层：code 域为什么崩了

### 3.1 现象

2302 代，99.6% 满分。日志长这样：

```
[gen 2293] 难度Lv5(...) best 1.000 ema 1.000 mean 0.931 div 0.355 hof 1209
[gen 2294] 难度Lv5(...) best 1.000 ema 1.000 mean 0.863 div 0.406 hof 1210
```

`best=1.000` 连着几千代。mean 还有 0.86~0.93 的波动，说明种群内部有差异，但**冠军永远是满分**。

选择压力在冠军这一层已经完全消失：反正大家都能满分，选中谁全看运气。

### 3.2 三层原因，一层比一层深

**第一层：题太简单。** 最初只有 7 族（calc/lru/bisect/dedupe/palindrome/fib/stack），都是几十行的经典小题，注入的 bug 也是"一眼能看出来"的。

**第二层：笔太强。** 换成外部 LLM 当笔之后，哪怕是盲改（不给报错），它读一遍源码就能定位。探针实测（`probe_new.py`，6 个硬核族）：

| 族 | 喂报错 | 盲改 | 梯度差 |
|---|---|---|---|
| topo | PASS | PASS | 0 |
| merge | PASS | PASS | 0 |
| quicksort | PASS | PASS | 0 |
| bfs | PASS | PASS | 0 |
| kadane | PASS | PASS | 0 |
| **dijkstra** | FAIL | FAIL | 0（但都失败） |

**五族梯度差为零**——盲改和喂报错一样能修，说明"脑诊断"这个基因维度根本没起作用，笔自己就把活全干了。

**第三层（最根本）：难度维度选错了。** 我把难度理解成"bug 藏得更深"，但对抗一个强笔，"藏得深"没有用——它能通读源码。**真正难住强笔的不是隐蔽性，是规模和交互**：跨文件、超长上下文、需求自相矛盾、性能约束。

dijkstra 是唯一一个两道都 FAIL 的——不是因为它 bug 藏得深，是因为**堆优化 Dijkstra 本身就难写对**（松弛条件、堆的更新、重复入堆处理）。这反而是个提示：**题目的绝对难度比 bug 的隐蔽度更有效。**

### 3.3 这个失败有普遍性

任何自博弈系统都会遇到：**当你把评估器交给一个比被评估者更强的模型时，评估就失效了。**

AlphaZero 没有这个问题，因为围棋的胜负是客观的、不可作弊的。而"代码修没修对"这个判断，一旦由强模型来做，就等于让强模型替被评估者答题。

**所以评估器必须比被评估者"笨"且"客观"**——只看测试通过与否，不看代码写得好不好。这也是为什么 code 域的评估只用 `pytest` 真跑，不让 LLM 打分。

### 3.4 评估器防护：堵住作弊路径（新增）

一个更隐蔽的问题：笔可以改**测试文件本身**，把断言删掉、写成 `print("All tests passed")`，fit 立刻 1.0。这是业界文档里点名的 coding agent 经典作弊姿势——测试不过就改测试。

修复：`write_fix` 里加了 `_vet_patch` 白名单，只允许改 `env.editable` 里列出的文件（`= [bug_file]`）。越界的文件名（尤其 `tests.py`）会被拒绝，并计入 `env.cheat_attempts`。

```python
# 只允许改白名单里的文件；越界的记入 cheat_attempts，不静默丢弃
```

这个计数本身就是一个观测指标：如果 `cheat_attempts` 持续上升，说明评估器正在被攻击，比 fit 更值得盯。

## 四、世界模型层：现在有的是课程，不是世界模型

区别很具体：

| | 现在有的（课程） | 世界模型该有的 |
|---|---|---|
| 世界做什么 | 冠军平台期 → 旋钮 +1 | 预测"这个策略下去会遇到什么"，主动构造 |
| 方向 | 单向变难 | 会针对冠军的弱点反制 |
| 状态 | 5 个整数 | 一个能推演的环境模型 |
| 会不会"出题" | 不会，只会调参 | 会生成新题型 |

现在的 `World.try_upgrade()` 就是"平台期加难度"，本质是**课程学习（curriculum learning）**，不是世界模型。这个区别必须说清楚，否则会高估自己做出来的东西。

---

### 4.1 第一次尝试：看冠军基因定向出题（**已做，被证伪**）

原计划（P1 第 4 条）是让世界盯着冠军基因出题：冠军 `parallel_try` 高（爱并行试），
就出「并行会污染状态」的题；冠军 `read_first` 低（不爱读码），就出「必须通读才改得对」的题。

**已实现**（`domains/code/adversarial.py`）：给 24 个 bug 模式逐个标注 counters 标签，
声明它克制冠军的哪个基因维度及方向（+ 克制偏高 / − 克制偏低），
出题权重 `= 1 + ALPHA × Σ 强度 × 偏离度`，偏离度由基因在 BOUNDS 内的归一化位置算出。
标注覆盖率 22/24（calc 的两个"一眼可见"弱题未标，走基准权重）。

**对照实验**（`domains/code/probe_adversarial.py`）：A 组 `champ=None`（随机，改造前行为）
vs B 组 `champ=<best_now.json 真实冠军基因>`（对抗），**同 seed 序列**，唯一差别是挑选策略。

| 阶段 | seed | 组数 | 随机成功率 | 对抗成功率 | 差值 |
|---|---|---|---|---|---|
| 修复前 | 201 | 30 | 0.967 | 0.900 | −0.067 |
| 修复前 | 301 | 60 | 0.950 | 0.983 | +0.033 |
| 修复前 | 401 | 50 | 0.980 | 0.980 | +0.000 |
| 修复前 | 501 | 50 | 0.860 | 0.880 | +0.020 |
| 修复前 | 601 | 50 | 0.880 | 0.860 | −0.020 |
| **修复后** | 701 | 60 | 0.967 | 0.950 | −0.017 |
| **修复后** | 801 | 60 | 0.967 | 0.983 | +0.017 |
| **总计** | | **360** | **0.9389 (338/360)** | **0.9389 (338/360)** | **+0.0000** |

**结论：对抗性出题对冠军成功率零影响。** 360 组里随机与对抗的通过数**完全相同**
（338 vs 338）。各 seed 差值在 −0.067 ~ +0.033 间摆动，方向随 seed 变，
均值 ≈ 0。这不是"效果小"，是**没有可归因于策略的效果**。

⚠️ **中途发现并修复了一个方向 bug**：counters 标注的标量解析
（`direction = -1.0 if strength >= 0 else 1.0`）把**正数判成了「克制偏低」**，
方向整个反了。修复后重跑两组，仍然零效果 —— 说明**零效果不是 bug 导致的，
是结论本身成立**。这一点很关键：差点因为 bug 而误判"修好就有效"。

**为什么没用（比结论本身更重要）**：

1. **天花板效应**：难度旋钮已拧到顶（size/depth/hidden/scaffold/resource 各 = 3，Lv15），
   冠军成功率仍有 86%~98%。在这么高的基线上，换选题策略没有可腾挪的空间。
2. **加权只在"选哪个 bug 模式"层面生效**，而题池里 24 个 bug 模式对强笔的
   难度大致相当。**对抗性出题只是在同一个（过低的）难度平面内重新洗牌，
   无法抬高天花板。**

**这条反面结果的价值**：它把 code 域的根因进一步钉死了——
不是"出题不够聪明"，而是**题池的绝对难度太低**（呼应 3.2 第三层：
「真正难住强笔的不是隐蔽性，是规模和交互」）。
所以下一步不该继续优化选题策略，而该**换题型**。

## 五、踩过的坑（都是真的，不是编的）

这些坑的共同点：**代码全对，但结果不对**。每一个都值一条铁律。

| 坑 | 现象 | 根因 | 铁律 |
|---|---|---|---|
| **4 道假题** | 注入 bug 后测试照样过 | 测试写的是 bug 行为；单次调用测不出可变默认参数；fix 写反；测试与修复冲突 | 题库必须先自证：golden 必过 + 注入必败。**没自证过的题等于没题** |
| **try_upgrade 卡死** | hidden 永远停在 1，盲改永不触发 | 维度升到 1 就被移出候选池 | 上限要显式写（`MAX_LEVEL=3`），不能靠"升满了自然退出" |
| **numpy.bool_ 崩** | `json.dumps` 报 TypeError | numpy 的 bool 不是 Python bool | 跨层传值前显式转原生类型 |
| **429 误判** | 以为限流，加退避没用 | `PROMOTION_MODEL_LIMIT_REACHED` = 免费额度耗尽，硬上限 | 429 要看 body。频率问题会自己好，额度问题不会 |
| **解析器只认 ```** | 笔写对了，但解析出空 | `re.match` 必须从块头匹配；pollinations 不用 ``` 包裹 | 解析别人的输出要用 `re.search` + 无包裹兜底 |
| **缓存投毒** | 笔明明可用，程序却跳过它 | `gen_cache.json` 里存着 429 时代的 `None` | 失败结果不进缓存，或缓存带 TTL |
| **重复进程** | `state.json` 的 gen 比日志小几百 | 两个进程写同一个 `evo/` 目录 | 单实例锁（同名互斥体 / PID 文件） |

最后一条是今天刚踩的：日志里 gen 2294 和 2059 交替出现，就是因为 19:17 和 20:10 各起过一个没带 `--out-dir` 的进程，跟我 21:25 起的三个抢同一个目录。

## 六、下一步怎么扩

按优先级排，前两条是"不做就白跑"：

### P0 —— 修评估器（code 域）

1. **难度继续往上**：`MAX_LEVEL=3` 写了但没触发，`levels.jsonl` 停在 gen 12。先查 `hist` 存的是 `ema` 而 ema 恒 1.000 → spread=0 → 应该触发才对。要么是被重复进程的 state 覆盖掉了，要么是 `--resume` 时 `world.levels` 没恢复。**这是 bug，不是设计**
2. **换难度维度**：把"bug 藏得深"换成"规模和交互"——跨文件调用链、300 行以上上下文、性能约束（O(n log n) 卡时间）、需求模糊（只给一句话）
3. **引入绝对难度**：dijkstra 证明了"题本身难"比"bug 藏得深"有效。补一批"笔也写不对"的题（堆优化、线段树、状态压缩 DP）

### P1 —— 世界从课程升级成对抗

4. ~~**看冠军基因定向出题**~~ —— **已实现并被证伪（见 4.1）**。
   240 组对照实验显示成功率差异为 **0.0000**，反制标签缺乏数据支持。
   结论：瓶颈不在出题策略，在题池绝对难度。此路暂不继续。
5. **世界也要进化**：把"出题策略"本身当基因来搜——出什么题能让种群的 div 保持在 0.3 以上。
   ⚠️ 注意：4 的证伪结果对 5 是个警告。如果题池本身区分度不足，
   搜出来的"最优出题策略"大概率只是噪声拟合。**建议先做 2/3 抬高题池难度，
   再谈出题策略的搜索**，否则是在噪声里找信号。

### P2 —— 跨域

6. **策略迁移**：三个域的基因语义不同，但"探索/利用"的平衡模式可以迁移。duel 的 `aggr/guard` 和 sgs 的 `aggr/guard` 是同构的，可以互相初始化
7. **补第四、五个世界**：卡牌构筑（Spire 式）、RTS（OpenRA 式）—— 这两个的规则复杂度远高于现在的三个，能把评估器逼到极限

### P3 —— 工程

8. **单实例锁**（今天刚踩）
9. **探针常态化**：`probe_hidden.py` 定时跑，把"冠军满分率"当健康指标报警
10. **数据落盘规范**：轨迹数据按域分离，避免这次 46MB 混在代码目录里

## 七、这套东西的定位

不是"通用 AI 自我进化"，是一个**自动平衡性 / bug 探测器**：

- 给定一个规则系统（游戏、卡牌、算法题），它能自动找出**规则里的漏洞**和**最优解**
- 冠军就是那个"探针"—— 冠军能赢到什么程度，暴露了规则有多容易被利用
- 难度升级机制本身，就是"这个系统的可玩性还有多少余量"的度量

这个定位比"通用自进化"实在得多，也是三个域里唯一被数据支持的部分。

## 八、业界研究对照：我们踩的坑，业界也都在踩

联网搜了近两年的 LLM 评测与对齐文献，发现我们踩的每一个坑都有对应的业界结论，这反过来验证了我们的诊断方向：

| 我们发现的问题 | 业界对应结论 | 来源 |
|---|---|---|
| LLM 当笔时，盲改和喂报错梯度差为零 | LLM-as-judge 存在位置偏差、冗长偏差、自我增强偏差；原始分数不可信，需工程化缓解 | W&B / pls.sh / Mirascope / DataVLab |
| 评估器被打穿（冠军 99.6% 满分），进化退化 | Reward overoptimization：代理奖励一路上涨，真实质量先涨后跌；"等平台期再停"会停太晚 | OpenAI (Gao et al. 2022) / ACE Journal 2026 / arXiv 2604 |
| 组内部分维度饱和导致优化方向失效 | TaRoS：组内奖励饱和会破坏优化方向，需对饱和组件降权 | USTC / 电信 AI 等 (arXiv 2511) |
| 笔可能改测试文件刷满分 | Coding agent 经典作弊：测试不过就改测试，或找能骗过校验的捷径 | 梁良心智模型（Goodhart 定律映射到 AI） |
| 难度维度选了"bug 藏得深"但强笔不吃这套 | Goodhart 定律：指标一旦成为目标，就失真；量化目标容易被钻空子 | 梁良心智模型 |

最有价值的一条来自 arXiv 2604.13602：**奖励黑客不是某次训练的偶然失误，而是"当指标成为目标，它就不再是好指标"的结构性保证**。这解释了为什么 code 域 2300 代全是满分——不是模型强，是评估器本身已经被优化目标同化了。

所以我们的核心判断——**评估器必须比被评估者"笨"且"客观"，只看 pytest 真跑，不让 LLM 打分**——和业界的 LLM-as-judge 局限性结论完全一致：当正确答案可枚举时（如代码测试通过与否），规则检查比 LLM judge 更可靠、更便宜。
